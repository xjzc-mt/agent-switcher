# AGS-0020 · 共享号池后台连续智能刷新策略与全端刷新按钮行为统一

- 状态：已关闭
- 发现日期：2026-11-25（2026-11-26 锁定基准节拍融合五层智能调度 + 全端手动刷新按钮行为统一，建议在 [AGS-0019](AGS-0019-tray-state-consistency-and-interaction.md) 完成后实施）
- 平台：全平台（额度刷新调度器）
- 来源：本地多人/多设备共用账号池场景需求

## 1. 现象与复现

1. **小菜单手动刷新按钮与主窗口功能不一致**：
   - 主窗口右上角「刷新全部」刷新当前所看平台的全部账号；而小菜单右上角 `[ ↻ ]` 仍沿用旧版「只刷两个平台的当前账号、不刷眼前的备用列表」，菜单栏 `Cmd+R` 又只调了 `loadStatus()` 本地重读，且 `refreshBatch` 批量刷新期间每完成单个账号漏调 `syncTray(true)` 未实时同步小菜单。
2. **跨页面/关窗连续性断层**：在小菜单或主窗口触发刷新后，切页面、收起小菜单或隐藏主窗口需继续跑完并同步全端；而当前 `canAutoRefresh()` 以 `document.hidden` 一刀切拦截，隐藏主窗口后后台自动刷新全部停摆。
3. **共享号池下的备用账号刷新矛盾**：备用账号池会被其他成员或设备共用消耗，需按时间自动刷新；但单纯固定间隔全量盲刷在设长周期（`15m / 30m`）时挑号瞬间易滞后，设短周期时又会对 `0%` 耗尽账号与闲置号空转浪费，且毫秒级固定等距脉冲易引发多设备撞车与 `429` 限流。

## 2. 根因与修复方案

### 具体修复方案（全端手动刷新按钮一致 + 保留设置时间作基准锚点融合五层智能调度）

1. **全 APP 手动平台刷新按钮行为 100% 一致（[src/tray-menu.ts](../../src/tray-menu.ts)、[renderer/tray.js](../../renderer/tray.js)、[renderer/app.js](../../renderer/app.js)）**：
   - 不给小菜单单独设计异构的手动刷新规则：**小菜单右上角 `[ ↻ ]` ＝ 主窗口右上角「刷新全部」＝ 系统菜单 `Cmd+R`**，统一调用同一套平台刷新逻辑——刷新**当前所选平台**的「当前使用账号 + 全部有效备用账号」（当前账号排第 1 顺位，备用账号按列表顺序入队；单账号刷新仅限账号详情内的刷新按钮）；
   - 修复 `refreshBatch` 期间每完成单个账号漏重建小菜单快照的问题：每完成一个账号更新状态后立即触发 `syncTray(true)`，使主窗口与小菜单逐个实时跳变；小菜单 `refreshing` 状态按当前选中平台是否有在途刷新准确联动。
2. **完整保留设置页双独立档位作为「基准节拍与总闸门」（[src/settings.ts](../../src/settings.ts) 保持不变）**：
   - 保留 `当前账号自动刷新`（`1m / 3m / 5m / manual`，$T_{\text{live}}$）与 `备用账号自动刷新`（`5m / 15m / 30m / manual`，$T_{\text{spare}}$），零新增设置开关；
   - **严格尊重 `manual` 总闸门**：任一范围设为 `manual` 时，该范围的后台定时、打开前排热刷、重置点补查全部关闭，仅响应主动点击刷新。
3. **第 1 层 · 后台常驻连续执行 + 系统休眠感知（[src/main.ts](../../src/main.ts)、[src/preload.ts](../../src/preload.ts)、[renderer/app.js](../../renderer/app.js)）**：
   - 任何入口触发的刷新一旦入队，切页面、收起小菜单、`Cmd+W` 隐藏主窗口均在后台完整跑完并同步全端；
   - 移除 `document.hidden` 对自动刷新的硬阻断，改接 Electron `powerMonitor`（`suspend / resume`、`lock-screen / unlock-screen`）：仅在系统休眠或锁屏时挂起自动调度，唤醒/解锁后立即补查已到期账号。
4. **第 2 层 · 决策时刻「打开即保鲜」（On-Open Top-K 前排热刷）**：
   - 当用户点开菜单栏小菜单或从后台唤起主窗口时，对未设为 `manual` 的范围，自动检查 **「当前账号 + 排名前 4 个可切换候选备用号」**（排除凭据失效与 `0%` 未到重置点的耗尽号）：凡距上次成功检查超过 $\min(T, 2\text{ 分钟})$（遵守底层 `>=30s` 冷却与失败退避）的，立即以高于普通后台轮询的优先级静默并发入队，1~2 秒内无感更新前排胶囊与排序。
5. **第 3 层 · 耗尽静默 + 重置点错峰回血（[src/accounts.ts](../../src/accounts.ts)）**：
   - 任一受限窗口已 `0%` 耗尽且持有未来 `resetsAt` 的备用账号，在到达重置点前暂停常规 $T_{\text{spare}}$ 轮询（`0` 无效开销），到 `resetsAt + (8s ~ 25s 错峰偏移)` 自动补查回血。
6. **第 4 层 · 围绕 $T_{\text{spare}}$ 的外部共用活跃自适应（动态呼吸）**：
   - **外部活跃加密跟进**：非本机激活的备用号若刷新检测到 `usedPercent` 较上次上升（跨重置点归零除外，说明外部设备/成员正在消耗），标记活跃剩余 `2` 轮，期间自动刷新基准周期缩短为 $\max(5\text{ 分钟}, 0.5 \times T_{\text{spare}})$，连续 2 轮无新增消耗后恢复 $T_{\text{spare}}$；
   - **长期闲置温和降频**：连续 `>= 3` 轮成功刷新 `usedPercent` 无任何变化的闲置备用号，基准周期温和放宽至 $\min(30\text{ 分钟}, 2 \times T_{\text{spare}})$。
7. **第 5 层 · 单账号独立随机抖动（Jitter 破除机械等距与整批齐射）**：
   - 计算常规自动刷新截止时间时，按「账号身份 + `checkedAt`」确定性哈希施加 `[-12%, +15%]` 比例偏移（`1m` 档保底 `>= 52s` 不触碰底层 `30s` 冷却锁；同一 `checkedAt` 下重复读 `dashboard()` 截止时间恒定，每次刷完更新 `checkedAt` 后自动获得新偏移），使同池多账号与多台共用设备自然均匀散开。

### 边界约束（不做什么）
- 不在设置页新增任何配置开关；不给小菜单设计独立于主窗口之外的第二套手动刷新规则。
- 不突破底层同身份 `30s` 最小查询冷却锁、最多 `3` 并发限制与 Antigravity 单通道串行限制；后台自动刷新与打开热刷失败均静默记入状态与退避，不弹 Toast 打扰用户。

- 主窗口、小菜单及 macOS 系统菜单按所看平台发起同一批查询。先查当前登录，随后按列表顺序查有效备用号。各平台独立显示进度，每次取得结果即同步。切页和关窗不打断批次。
