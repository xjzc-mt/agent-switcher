# 应用内下载更新

## 范围

「设置 → 应用与更新」上行显示版本与可用操作，下行提供自动检查、导出故障报告和 GitHub 入口。发现可下载新版时，下载安装包按钮启用。应用内负责检查、下载与校验，安装仍由用户打开 DMG、退出 AgentSwitcher 后拖入「应用程序」替换。

更新器匿名访问固定的 `xjzc-mt/agent-switcher` GitHub Releases。接口返回 404 时，设置页显示暂未取得可用版本。正式分发需要用户能匿名读取发布记录、DMG 和签名清单。如改用专用发布仓库，应同时更新应用、官网和 README 的入口，并为旧用户提供首次手动升级方式。

## 行为

- 打包运行时默认每 24 小时至多自动检查一次，手动检查遵守服务端限流；开发运行仅手动检查。可取消勾选自动检查，不再提供忽略版本；旧缓存中的忽略记录不影响新版展示，检查失败不能显示已是最新。
- 更新说明位于新版号旁，仅有说明时显示，默认收起；同版刷新保留展开，重新进入设置或换版时收起。下载中、校验中及下载后以当前操作为主，安装步骤在下载完成后展示。
- 稳定版本按版本号比较，不按发布时间判断；当前应用内下载仅支持 macOS Apple Silicon。缺少对应安装包、附件有歧义或没有校验信息时，可通过唯一的 GitHub 按钮前往项目主页查找发布版本。
- 一次下载固定版本、资产与校验值。使用 Electron 下载能力，独立于窗口生命周期；文件写入系统下载目录内的 AgentSwitcher 专属临时目录，不覆盖已有文件。
- 应用用内置 Ed25519 公钥验证安装包同名的 `.signed.json` 清单。签名绑定项目、版本、文件名、大小和 SHA-256。GitHub 同时提供 digest 时也要一致。签名缺失或不匹配时，只显示发布信息与项目页。
- 下载进度、取消和失败显示在设置内。服务器声明的长度与签名清单不符时取消接收；长度未知时，收到的字节一旦超限就取消并清理临时文件。完成时和打开前均核对文件大小与签名清单中的哈希。重启会重新验签缓存，旧版只保存哈希的下载记录需要重新检查签名。真正退出时取消未完成下载，只关闭主窗口时下载继续。
- GitHub 网络失败时，网页下载入口也可能无法访问；当前不使用第三方代理或镜像。
- 发布清单签名用于验证 AGS 发布者。macOS 的应用签名、公证和下载来源提示继续按系统规则处理。

## 退出与安装

打开安装包成功后，原位置提供「退出 AgentSwitcher」。此按钮、菜单退出和 Cmd+Q 走同一个退出协调过程：暂停接受新的账号写入，等保存、切换、导入和续期回存等已开始操作结束；有独立登录、待确认导入或未完成下载时，说明取消范围并默认继续使用。确认后清理临时登录与下载，再退出。退出失败保留应用，可重试。

安装只替换应用文件，不修改 `com.agent-switcher.app`、账号池路径或 Keychain 条目，不关闭 Codex/Antigravity。打开 DMG 不表示更新完成；重新启动后以实际应用版本为准。单独从源码安装的 `ags` CLI 不随 DMG 更新。

## 发布流程

1. 增加 `package.json` 版本号，运行 `npm run dist`。
2. 在持有项目发布私钥的机器，用 `npm run release:checksums -- --sign-key /path/to/private.pem release/AgentSwitcher-版本-arm64.dmg` 生成 `SHA256SUMS` 和 `AgentSwitcher-版本-arm64.dmg.signed.json`。前者保留给手动核对或旧版客户端。
3. 在 GitHub Draft Release 上传 DMG、对应签名清单和 `SHA256SUMS`，tag 使用 `v版本`，说明用户可感知的变化及最低系统要求。
4. 核对文件、版本、校验与安装后发布为稳定版。不要覆盖已发布的同版本包；修复使用新版本号。

首次安装带验签功能的版本时，请从可信渠道取得应用及其内置公钥。旧版只核对哈希或没有更新功能，均可手动安装。使用新版检查历史无签名 Release 时仍可访问项目页。

## 验证边界

业务与界面测试使用临时目录、模拟 Release、模拟下载事件与假账号，覆盖无发布版本、版本选择、下载损坏、取消、缓存及退出保护。真实公开 GitHub Release 下载、macOS 下载来源属性和旧版拖动替换仍需首个正式发布包做验收；不能把测试安装包描述为已发布新版。
