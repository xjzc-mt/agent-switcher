# AGS 界面设计约定

AGS 是多 Agent 账号管理工具，界面服务于识别账号、切换账号和比较可取得的额度。风格保持简洁、紧凑、直接；新功能沿用现有组件和信息密度。本文按 2026-11-18 工作区代码核对，并区分现状与待实现方案；代码核对不替代本批 UI 与成品验收。

## 开始设计前

- 先看 [账号管理流程](account-management.md)，确认当前 Agent 的能力、凭据方式和额度来源；同名套餐在不同 Agent 下不是同一种业务。
- 核对实际页面与 `renderer/index.html`、`renderer/accounts.css`、`renderer/app.js`；基础结构在 `index.html`，当前公共组件与视图变体在 `accounts.css`；同一选择器的同一属性只保留最终有效定义，条件样式仍按媒体/容器范围维护。
- 用现有测试凭据查看目标状态，避免读取真实凭据；示意沿用页面尺寸、字号、按钮和信息层级，不重画一套外壳。

## 已有视觉基线

| 项目 | 当前值或行为 |
| --- | --- |
| 页面与卡片 | 浅灰蓝页面 `#f7f9fc`，白色卡片，边线 `#e2e7ef`；备用卡片无阴影、无悬浮抬升 |
| 文本与操作 | 主文字 `#172033`，次文字 `#66758c`；品牌色 `#4f46e5` 用于主要操作和选中状态 |
| 字体 | 系统无衬线字体；昵称 13px，邮箱、周期、倒计时 11px，套餐组标题 12px |
| 卡片尺寸 | 宽 180–208px，间距 8px，圆角 9px，内边距上下 7px、左右 8px；稀疏组与密集组同宽 |
| 切换按钮 | 高 26px，字号 11px，圆角 6px，浅紫描边；凭据失效时显示「更新」 |
| 套餐组 | 小标题、普通数字计数和细分隔线；相邻组间距 15px，不加独立面板底色 |
| 额度 | 数值用小面积底色提示充足、普通、偏低、耗尽和历史状态；备用卡片不放额度进度条 |
| 当前账号 | 信息较详细；备用账号池紧凑，主要操作是切换，详情承接次要信息 |

卡片高度由资源内容决定。当前测试样例中，双周期卡片为 103px，单周期卡片为 84px；这是现有样式的测量结果，不是所有 Agent 共用的固定高度标准。

## AGS 品牌图标

- macOS 应用图标采用无内框齐平亮白微凸瓷面底板，配 80% 满高宝石色三段高门与放大的五个圆润 Agent 角色，自然接触投影承托主体。菜单栏使用同轮廓的单色模板。应用图标见[正式图标](../packaging/app-icon.png)。
- 设置「应用与更新」使用 28px 彩色门标，置于应用名称和更新状态两行文字左侧，间隔 8px，与两行整体垂直居中。更新说明、下载进度及操作提示在下方独立展开。
- 账号页用平台图标标识身份，用数值和状态色表达额度。

## 风迹装饰（已实现）

- Codex 与 Antigravity 共用一份静态蓝紫流线，仅在当前账号身份区的空白处展示；页面及页尾保持原有浅灰蓝底色，不增加装饰或局部渐变。
- 身份区装饰只占剩余宽度，不增加主卡片高度；长名称或窄窗口优先显示身份与操作，流线随空间收缩。额度区保持白底，模型名称与实际额度结构沿用原流程。
- 主卡片流线不拦截点击，高对比或强制颜色模式下隐藏；无动画、新依赖或按平台复制的装饰组件。页面留白随账号数量自然变化，不为装饰调整布局或滚动高度。
- 侧栏、顶栏、备用卡片与单行视图保持原样，包括尺寸、间距、分隔线和额度状态颜色；生成效果图仅作为装饰方向，不替代组件规范。

## 跨平台共用约束

- 顶栏是唯一的窗口拖拽区，只有顶栏内的交互控件声明 `no-drag`；页面根节点与滚动内容保持默认 `none`，避免内容滚动后继承的禁止拖拽矩形覆盖顶栏。
- 页面模态弹窗打开期间，顶栏统一暂停拖拽；弹窗关闭后自动恢复，防止穿过遮罩拖动窗口。详情、添加账号与导出密码弹窗共用此规则。
- 身份区、操作按钮、周期额度单元、列表表头和账号详情共用已有结构与样式。平台差异决定数据、周期、主次顺序和能力；不另写一套同用途组件或按平台覆盖间距、字号、分隔线。
- Antigravity 主卡片、备用视图、分组标题和菜单栏使用套餐简称 `Pro` 或 `Ultra`。官方 CLI 返回已确认的 Ultra 套餐 ID 时显示 `Ultra 5×` 或 `Ultra 20×`。详情保留完整套餐名称，未知名称原样显示。
- 账号名称沿用现有 100 字符上限，完整保存；卡片按可用宽度省略长名称，不因展示调整修改已保存的昵称或登录邮箱。
- 备用卡片沿用 `account-card` 与 `card-resources`：内边距 7px 8px，身份区到额度区间距与上内边距均为 6px，中间一条 1px 边线。双周期列间距 8px，第二列左边线 1px、左内边距 7px；单周期不补竖线或空列。
- 同类额度单元保持一致；详细双列沿用列宽与竖线，次要摘要使用独立的紧凑横排，不强套详细双列的分隔规则。摘要统一字号、颜色、间距与提示行为，只定义一份共用样式。
- 单行视图沿用套餐名与列名共处的 32px 表头、44px 账号行；表头与数据共用列宽。周期标题只保留「5h 剩余」「7d 剩余」等必要信息，名称释义与重置说明放到提示中，不加第二层表头或常驻图例。
- 单行视图的昵称、额度、重置时间、操作始终处于同一个 44px 账号行，不横向滚动、不退回多行卡片。仅名称列随窗口收缩；其他列按实际周期、日期显示模式及整个平台账号池是否具有 Credits、重置卡确定固定宽度。日期模式保留完整重置日期；备用窄卡只省略日期前的重置图标，不裁切日期。
- 右键沿用现有账号详情弹窗及其键盘入口；复用 `accountDialog`、`accountDetailsContent` 与 `account-detail-*` 样式。模型差异只增加数据行，不增加另一套菜单、模型分区面板或专属弹窗。
- 详情标题区的关闭、改名操作共用 26px 方形图标按钮；关闭使用现有线条图标，默认透明，悬停只显示浅底色，键盘聚焦保留品牌色轮廓。
- 所有平台共用颜色状态、数字格式、重置显示偏好与提示组件。提示补充全称、来源和重置时间，不承载唯一的关键额度数值。
- 需要改变公共视觉规则时，先修改本文的对应规则，再改公共样式，并检查受影响的平台。预览也遵守这些规则，不能把另画的组件当作实现依据；不为落实约束另建组件框架。

## Antigravity 主次分层（已实现）

- 当前账号：Gemini 作为主额度直接显示实际周期、剩余数值、重置时间与进度条，不重复写「Gemini」标题。次要额度由实际返回的模型组与周期生成，显示模型全名、周期、数值和已取得的重置时间；不为 Argon 写专属布局、固定列数或按宽度隐藏模型。短内容按自然宽度并排，放不下时整组换行；单组仍过长时名称与周期区域分行，每个周期及其数值保持相邻。不加「全部额度」入口或标题，不截断主卡片模型名称。
- 备用卡片：主额度沿用共用双周期结构；Claude / GPT 使用独立的次要摘要行，左侧优先显示全称，卡片自身宽度不足时才用 `C/G`；阈值按现有字号及两个 `100%` 的占位确定，同宽卡片不随余额变化切换名称。右侧紧凑排列周期和百分比，无竖线、不对齐主额度的双列，不挤压数值、不为名称增加行高。缩写全称与重置时间放到提示中，不显示常驻图例；Argon 等其他组放进现有右键详情。
- 备用单行的表头依次显示套餐名、5h 剩余、7d 剩余、Claude / GPT 和操作。每个账号占一行，Claude / GPT 列显示周期与数值，重置时间通过提示和详情查看。
- 主额度按返回的模型组身份识别，不因取消标题而依赖数组第一项；缺少 Gemini 时显示未取得，不将其他组冒充主额度。不存在的模型组不补位，应有但未取得的额度显示 `—`。
- 默认比较与排序围绕 Gemini；Claude / GPT 与 Argon 不和 Gemini 合成一个剩余比例。其他组耗尽应在其摘要或详情反映，不能把主额度正常的账号标成 Gemini 不可用。同套餐优先比较最短周期，长周期耗尽时当前可用值按零处理，再比较长周期剩余。
- 三种视图已接入 GUI；摘要复用 `quotaCell`，表头共用列表列宽，账号详情保持原入口。卡片内容宽度达到 189px（外宽 207px）时显示 Claude / GPT 全称，阈值按两个 `100%` 验证。

## 按 Agent 与额度结构展示

- Codex Plus 的双周期卡片：5h、7d 左右分列，每列上面是剩余比例、下面是重置时间。
- Codex Pro 的单周期卡片：`7d 剩余比例` 与重置时间横排，占一行；不为对齐 Plus 人为加高，也不补一个并不存在的 5h 占位。
- 侧栏依次显示 Codex、Antigravity 和置灰的 Claude Code。最后一项仅在悬停或键盘聚焦时提示「暂不支持」，没有账号计数和操作入口。添加账号仅列出前两个平台。
- Antigravity macOS 个人账号按官方模型组展示实际的 5h / 7d 等周期，复用紧凑数值、重置时间和详情；不同套餐的模型组不强行补齐，不显示未提供的 Credits。其他未支持额度的平台模式仍只显示身份和已知套餐。
- 后续平台可能有不同周期、多个额度桶或不同能力。复用身份与操作区域，资源区按实际业务调整，不把 Codex 的两周期布局视为通用标准。
- 区分「该平台或套餐没有这个周期」和「应有的周期本次没取得」。只有后者需要缺失提示，不从缺少字段推断余额为零或凭据失效。

## 设置页（已实现）

- 页面标题和侧栏入口统一为「设置」，进入后保留「返回账号」入口；内容在主工作区居中，最大宽 560px，区块间距 20px，文字仍左对齐。
- 使用「偏好设置」「数据清理」「应用与更新」三组，标题后接现有边线色的细线；更新卡片上下两行之间增加同色分隔线。
- 偏好设置的名称与选项各占同一行，行高约 46px，右侧分段框统一 `168px` 等宽、内部选项 `1fr` 均分对齐（两格正中分割线与四格正中分割线重合）：额度重置时间选择「倒计时 / 日期时间」，当前账号自动刷新选择「1分 / 3分 / 5分 / 手动」，备用账号自动刷新选择「5分 / 15分 / 30分 / 手动」，无痕登录入口选择「自动打开 / 仅复制链接」。各行独立互不耦合，选中后立即保存，不增加格式示例、关闭说明或悬停提示。
- 保存失败恢复已保存的选项，保留更新状态、展开说明及下载进度；账号页面和登录流程继续使用同一份设置。
- 数据清理显示「Codex 本机账号数据」，说明为「与 AI 助手的对话，选择要清理的历史遗留账号和数据」；按钮保留复制图标和「复制指令」，只复制现有指令。

## 应用与更新（已实现）

- 版本、更新状态及 GitHub 项目入口只放在设置末尾的「应用与更新」，主页面、侧栏、顶栏与托盘不增加版本号、红点或更新提示。
- 使用「双行直达」布局：第一行左侧为全称 AgentSwitcher、当前版本及简短状态，右侧为当前阶段操作；第二行左侧为原生「自动检查新版」勾选框，右侧固定一个带图标的 GitHub 按钮。
- 「下载安装包」保留固定位置，尚未取得可下载新版时禁用，发现可下载新版后启用并使用品牌主色；下载中变为取消，校验中禁用，下载完成后按本机安装方式只显示一个主按钮「立即安装并重启」或「打开安装并退出」。
- 更新说明仅在有新版、提供说明且尚未开始下载时出现，入口放在新版号旁，默认收起；展开后显示纯文本，不重复文件名、平台与发布时间。相同版本的状态刷新保留展开状态，重新进入设置或换版时收起。
- 无可下载新版时在状态旁提供「检查新版」，有可下载新版时以「更新说明」取代；不保留「忽略此版本」。下载失败保留重新下载，检查失败可重试。
- 下载进度、取消、重试、校验和失败信息均在此区域内展示；进度变化不重建整个设置页，不丢失键盘焦点。后台检查不弹提示。
- 仅在 macOS 需要手动替换时，在下载完成后提示将应用拖入「应用程序」并重开。主页面切换或关闭窗口不取消下载，真正退出时统一处理。
- GitHub 按钮始终打开固定项目主页，不再显示发布记录、复制链接或额外下载入口，不显示 Star 数量，不求赞。私有仓库或无 Release 时说明暂未取得可用版本，不能显示已是最新。

设置的「应用与更新」提供「导出故障报告」。点击后直接选择本地保存位置，取消后回到设置页。

## macOS 菜单栏小菜单（当前源码）

- 260 点宽的面板一次显示一个平台。当前账号区用绿点、遮蔽完整邮箱的昵称和套餐标识身份。单、双周期额度均占 66 点高，剩余百分比用 17 点粗体，下方是 4 点进度条。重置时间跟随主窗口的倒计时或日期偏好，缓存显示「上次记录」。
- 备用账号按账号池顺序直接显示。「点选切换」右侧的周期表头与每行两个 44×19 点的额度胶囊对齐，沿用主窗口的充足、常规、偏低、耗尽和缓存色。单周 Codex Pro 的 `PRO` 在昵称旁，5h 列以透明虚线槽显示「不限」，7d 列显示周额度。缺失值显示「—」，异周期标出实际周期。
- 列表最多显示 5.5 行，超过后仅名单滚动。底栏固定放置「打开主窗口」与「退出」。上下键选择账号，Escape 关闭；刷新推送保留焦点与滚动位置。普通切换在面板里完成，需要确认或更新凭据时显示主窗口。[菜单说明](navigation-menus.md)

## 异常与次要信息

- 查询失败有历史额度时保留并弱化数值，通过小警告和详情说明是上次记录；没有历史额度时显示「查询失败」。凭据失效单独显示，沿用已有错误判断和更新入口。
- 账号详情在状态行下方直接显示失败原因和恢复建议。长说明自然换行，与状态标题同文时只显示一次。历史数值标为「上次额度」，底部保留上次更新时间和刷新入口。
- 已保存且需更新凭据的账号在详情底部提供「更新凭据」。点击后关闭详情，进入该账号的更新流程。其他账号沿用现有详情操作。参见 [额度刷新](refresh-behavior.md)。
- 重置卡使用小图标与数量，Credits 沿用已有边角或列表展示；不为了统一图形而扩大卡片。
- 颜色必须同时有数值、文字或图标说明；图标按钮保留可访问名称、键盘操作和可见焦点。

## 账号池展示与排序

- 备用标题、计数、搜索、视图切换、管理和添加按钮保持原来的全宽布局。只有下方单行列表按内容宽度居中；缩小窗口先消耗两侧留白，留白用完后列表及名称列一起收窄，放大时反向恢复。
- 名称理想宽度取当前平台完整备用账号池实际显示名称的最大像素宽度，排除当前使用账号，至少六个汉字（当前 13px、600 字重实测约 80px）。实际宽度不得超过扣除固定列及间距后的剩余空间；80px 不是压缩下限，不使用百分位或 240px 上限。超长名称省略并可悬停查看完整名称及邮箱。搜索、折叠不以可见子集重算理想宽度；切换账号后按变化后的备用账号池重新计算。
- 所有套餐组共用列表边界和列位置。Codex Pro 的 7d 额度对齐 Plus 的 5h 额度，Pro·100／200／500 档位对齐 Plus 的 7d 额度；Pro 实际返回多个周期时，在第一额度单元内部紧凑排列，保留完整数据。其他套餐按真实周期显示。
- 窄窗口实测 Enterprise 标题可能超出名称列，因此只对放不下的套餐文字省略并提示全称；箭头、计数和异常提示保持完整。折叠组的标题可利用已隐藏的额度表头区域，避免名称、计数和异常提示挤在一起，列表宽度不变。
- Credits 按完整备用账号池统一决定是否占列：全无则不占列，部分有则其余行留空；未知余额保留「—」，长余额省略并悬停查看完整值。过滤、折叠不改变列宽。
- 窗口最小宽由三张最小备用卡片、两处卡片间距、左右内容边距和当前侧栏宽度计算；卡片和窗口共用尺寸来源。当前为 `3 × 180 + 2 × 8 + 2 × 20 + 152 = 748px`，折叠侧栏时为 `3 × 180 + 2 × 8 + 2 × 12 + 56 = 636px`，最小高度仍为 620px。列表不另设窗口下限。
- 默认窗口宽取「默认展开侧栏放下三张最大卡片」与「折叠侧栏放下四张最小卡片」所需宽度的较大值，与卡片和边距共用配置。当前为 `max(832, 840) = 840px`，默认高度保持 700px；展开时三张 208px 卡片，右侧额外留白 8px，折叠后四张 180px 卡片。当前不记忆用户调整后的窗口大小。
- Plus 缺少应有周期时，保留两列结构，缺失处显示 `—` 和「未提供」。查询失败有历史额度时保留原有周期结构；无历史额度的查询失败、凭据失效只显示一行状态，同组同行的外框按最高卡片对齐，单行状态在资源区域内自然居中。Pro 单周期及全为失效账号的行保持紧凑。
- 备用账号的凭据已过期、明确遭拒、不可读或有待验证的替换凭据时，统一排入最后的「凭据失效」组。卡片和列表在状态旁标出原套餐。同一份凭据此前只查到套餐时也保留该标签，套餐未知时省略。网络故障与待首查账号仍排在原套餐组尾部。
- Plus 按当前可用的 5h 剩余、再按 7d 剩余降序；周额度耗尽时当前可用值按零处理。Pro 单周期按档位权重乘周剩余比例估算排序；实际返回额外周期时也考虑其限制。该分值不是接口返回的真实余额，低余额颜色不影响额度排序。
- 套餐标题旁加小箭头折叠，保留现有标题行高度；只在折叠时用小警告与数量提示内部异常，完整原因通过提示和展开查看。
- 组间调序放进现有「管理」模式，上移、下移按钮只在管理时显示；组内账号仍自动排序。「凭据失效」组固定置底，可折叠和批量管理。搜索「凭据失效」显示整组，搜索「待验证凭据」或「凭据不可用」仅显示对应状态的账号。默认 Pro 在 Plus 前，记录各 Agent 自己的组顺序和折叠状态。
- 管理模式点击账号卡片或单行的名称、额度、空白处均可选中或取消，选择框仍保留原生键盘操作；整块点击与选择框点击共用一次选择处理。独立操作按钮保留自身行为，普通浏览模式不触发选择。
- 排序仅维护当前自动比较规则；已移除没有界面入口的旧昵称排序、重置时间排序分支。样式仅保留当前元素和实际生效的声明。
- 首次展开各组，之后尊重用户选择；搜索时临时展开匹配组，清空后恢复。搜索期间暂停折叠和调序，避免误改未显示组的位置。已有平台没有套餐分组时，不为了加入折叠而强造分组。

## 验证与维护

### 账号移除和清理辅助（已实现）

- 复用账号详情中的删除确认区，异步预览所选账号及同身份备份名称/数量；未取得预览时禁用执行，失败保留内联错误并提供「重新核对」。取消后忽略迟到的预览结果。
- 当前账号提供默认不勾选的「同时退出当前客户端登录」。不支持时禁用并说明原因；只从 AGS 移除时明确保留客户端登录、历史和项目，选择退出时仍保留历史与项目。
- 预览和勾选状态在额度更新时保持，键盘焦点不丢失。批量操作按同身份预览去重，确认范围，始终保留客户端登录；部分失败保留未完成选择。
- 设置中的「数据清理」区域使用上述文案和复制入口；不显示历史账号名单或常驻长 Prompt。复制后只提示已复制、尚未执行清理。
- 当前账号未入池时，切换前用现有原生确认对话框选择取消、不保存并切换、保存后切换；默认保护凭据。已入池账号切换不增加步骤。
- `tests/ui-cleanup.cjs` 覆盖删除预览、取消与失败、退出选项、批量去重、设置只复制，以及不同窗口宽度；凭据正确性由业务测试覆盖。

- 视觉改动检查单周期、双周期、缺失、查询失败、凭据失效和无额度平台；同时核对宽度、对齐、溢出与关键交互。
- `tests/ui-interactions.cjs` 用长账号池覆盖两平台、卡片/单行、展开/折叠侧栏的多处滚动位置，以及设置页滚动和弹窗开关；检查禁止拖拽矩形是否侵入顶栏，不能仅断言顶栏声明了 `drag`。原生区域变化另用 Electron 拖拽区域调试日志核对。
- 复用 `tests/ui-layout.cjs`、`tests/ui-account-errors-import.cjs` 和 `tests/ui-providers.cjs` 的相关场景；后者调用 `tests/ui-antigravity.cjs` 检查主次布局、窄卡简称、日期显示与缺失模型；`tests/ui-account-groups.cjs` 验证分组交互与异常卡片密度，`tests/account-policy.test.cjs` 验证排序，不重复跑与改动无关的检查。
- 综合 UI 测试保留登录、导入、批量导出、特殊名称和搜索等完整操作；布局、刷新、改名交给对应专项，避免同一流程重复验证。业务测试保留不同的凭据安全边界，同一边界以最完整的场景为准。
- 新的设计决定在实现后更新本文的状态；历史示意、发布说明和旧验证报告不替代当前设计约定。
