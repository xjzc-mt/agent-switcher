# 账号管理流程

本页记录 1.0.1 的账号管理流程及标明的后续源码改动。平台范围和升级方式见[版本说明](release-1.0.1.md)。

Antigravity 的当前实现见[当前账号与备用额度](#当前账号与备用额度)，设计目标与通过条件见[账号管理闭环与十四问](#antigravity-lifecycle)。

当前管理平台为 Codex（`codex`）和 Antigravity（`agy`）。项目没有单独的 Gemini CLI 适配器，讨论 Gemini 时需明确是否指 Antigravity。

旧备份混有已移除平台的账号时，导入预览显示跳过的数量，仍可选择其中的 Codex 和 Antigravity 账号。

## 当前共同流程

1. 添加账号：通过平台登录入口取得凭据，或导入已有凭据，再保存到账号池。是否改变当前客户端登录取决于平台，见下表。
2. 管理账号：账号池复用保存、身份去重、改名、删除、导入与导出；保存或导入成功不代表已切换客户端。
3. GUI 切换：先判断当前适配器是否支持；若对应桌面客户端正在运行，提示用户完成或停止任务，确认后正常退出。客户端原本未运行时不自动启动。
4. 应用账号：`useAccount` 同步当前已入池凭据，再调用平台的 `use` 应用目标凭据。当前身份未入池时，GUI 先明确选择「保存后切换」或「不保存并切换」；CLI 使用 `--save-current` 或 `--discard-current`。保留凭据版本检查和写入失败恢复。
5. 更新界面：重开此前退出的客户端，显示切换结果并更新账号列表；Codex 与受支持的 Antigravity 随后按缓存规则查询额度，额度查询不作为切换成功的前置条件。
6. CLI 切换：`ags use` 调用同一个 `useAccount`，检测到对应桌面客户端仍运行时要求先退出，不执行 GUI 的退出与重开操作。已有终端会话需自行重开。

当前“已切换”表示本地凭据已应用并通过写入结果检查；没有重开后读取桌面实际账号的步骤。重开失败会提示手动启动，不撤销已经完成的凭据切换。移除默认保留客户端登录；当前账号可在支持的认证存储下显式选择退出并移除，见下文。

### Windows x64

发布版 1.0.1 使用独立安装的 Codex CLI 登录和查额度。切换前须手动关闭共用登录的桌面、CLI 或 IDE。系统凭据库、组织限制等无法按文件处理的环境会在写入前提示原因。Windows 独立测试用户的端到端验收仍待完成。[Codex 认证存储](https://developers.openai.com/codex/auth/)

源码版支持从 Mac 的加密备份导入 Codex 文件登录和 Antigravity 2.x 个人登录。导入后在 Windows 选择账号并点「切换」。Codex 优先使用已配置的官方 CLI、PATH 或 npm 安装，再查找桌面解出的运行组件。Antigravity 需要安装官方 Windows x64 CLI。备份记录导出时的登录状态，两台设备后续的续期结果各自保存在本机。

仅安装 Microsoft Store 版 Codex 时，先打开一次桌面端。AGS 在用户的 `OpenAI/Codex/bin` 和官方包 `OpenAI.Codex_2p2nqsd0c76g0` 的 `LocalCache/Local/OpenAI/Codex/bin` 中选择最新的可用组件。切换时确认「退出并切换」，AGS 会请求关闭原桌面窗口，等桌面及其 Codex 后台进程退出后再应用登录。商店版通过已注册的应用入口重开，常规安装从原位置重开。共用登录的独立终端或 IDE 会话需要手动结束。

Windows 只检查当前登录会话。AGS 核对桌面主进程的归属、安装路径和创建时间后，向它拥有的窗口请求关闭。已确认属于该桌面的沙箱子进程即使隐藏了路径或用户信息，也只需等待退出。通用进程名 `language_server.exe` 需要官方路径佐证才会阻止切换。

Antigravity 的短凭据保存到当前用户的 Windows 凭据管理器。完整凭据超过 2,560 字节时，切换流程会请求确认，将桌面和 CLI 的两份官方登录文件分别写入并核对。备用账号的官方 CLI 使用单次查询专用的 Windows 受限令牌与临时主目录，可沿用用户配置的本机代理。只有 Job 内所有写入进程结束且回执已核对，AGS 才接受续期结果。源码模拟使用合成登录，真实 Windows 联验见 [AGS-0008](../issues/AGS-0008-windows-runtime-and-sandbox.md)。[Windows 凭据大小限制](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)

新建或改名时统一检查 Windows 保留名、非法字符和尾点。旧 macOS/Linux 账号仍可使用并改名；旧备份中的不兼容名称可在导入预览中修正，再确认恢复。[Windows 文件命名](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)

### 本地故障报告

桌面端自动保留最近 7 天内的有限操作记录。记录包含 AGS 版本、系统平台、操作来源、相对耗时和预定义的步骤及结果，按数量滚动并优先保留故障现场。源码预览会在版本号后附上应用代码摘要，方便区分同版本的不同修改。记录中的账号标识在导出时换成报告内编号。额度查询可区分缓存、只读和实际启动查询等路径。刷新没有取得新额度时，沿用已知的上次成功时间。

Codex 查询出错时，报告会标明失败发生在初始化、读取账号、读取额度还是续期。官方 CLI 明确返回的 HTTP 状态、标准 RPC 错误码和已识别的错误原因也会保留。只有通用错误时，报告保留该步骤，具体原因留空。

「设置 → 应用与更新 → 导出故障报告」只读取已有记录，将脱敏 JSON 保存到用户选择的文件。导出后可私下交给维护者。邮箱、账号原名、凭据、完整路径、命令参数及 CLI 原始输出均不进入报告。

## 凭据安全与迁移（已实现）

- 账号池中的 Codex 与 Antigravity 凭据，以及池内导入暂存凭据，使用 AES-256-GCM 加密；凭据格式与平台作为认证附加数据。昵称、额度快照等元数据保持原格式，客户端使用的原生凭据文件/Keychain 也保持官方格式。
- GUI 启动及 CLI 操作前在账号池锁内迁移旧明文文件：先写加密临时副本、从磁盘回读并解密比对，再核对原文件未变化，最后原子替换。逐文件完成，失败不会删除对应原件；已经成功迁移的文件仍可使用。损坏的密文、丢失或不匹配的密钥不会触发覆盖或重新生成密钥。
- macOS 主密钥由 Keychain 保管，GUI 与 CLI 共用；密钥通过标准输入写入，不进入进程参数或账号池。Windows 使用 CurrentUser DPAPI 包装密钥，Linux 使用 Secret Service（`secret-tool`）；Windows CI 已用测试账号池验证 DPAPI 跨进程解密。Linux `secret-tool` 仅在退出码为 1 且标准错误为空时视为缺少密钥。密钥环通信或解锁错误会提示系统安全存储不可读。Linux Secret Service 仍待实机验收。系统存储不可用时拒绝新的凭据写入，不静默回退成明文。
- 本机加密文件依赖系统密钥，迁移机器使用现有 `.ags` 密码加密导出/导入，不直接复制账号池目录。新导出的加密备份使用显式 `AGS2` 版本头（密码做 Unicode NFC 归一化，头部附带受 GCM 认证的有界 `scrypt` 参数 `N=65536, r=8, p=1`），导出端统一校验单文件与 `_meta.json` 上限、解压总体积及最终加密包体积上限（确保导出成功的备份同版必可导入），导入端在分配解压条目对象前按实际解包器同一目录范围校验非分卷/非 ZIP64 布局、中央目录条目数上限与声明体积；当前版本兼容恢复旧 `AGS1` 备份及超过 200 个账号的历史大备份，但旧版（如 v1.0.0）无法直接解密新版导出的 `AGS2` 备份文件。
- 当前进程缓存已成功解锁的读取密钥，避免每次刷新界面访问系统密钥服务；重启后重新获取。启动扫描已加密文件时，整批读取一次系统密钥，即使首批文件全部损坏也逐卡报告；单个凭据写入及旧明文迁移在替换原件前重新读取系统密钥并校验落盘内容。凭据损坏、目录名异常或凭据路径被替换为目录或符号链接时，面板和 CLI 标记相应账号，健康账号仍可操作。密钥丢失或替换时停止写入，当前仍已解锁的账号可先导出恢复备份。旧版本不能直接读取迁移后的加密账号池，降级前须用目标版本兼容方式准备凭据。
- 批量导入在同一把账号池写锁内准备新增账号和待验证更新，每份暂存密文都读回解密并与输入核对。保存、更新、删除和导入先按固定顺序取得涉及身份的额度锁，再获取账号池锁并重检身份。已建钥的正常批次在开始、准备完毕及提交结束时各核对一次系统密钥。macOS 把这三次核对和首次建钥交给工作线程，等待系统服务时主线程仍可处理界面事件。发现换钥或丢钥会撤销本批变更，其他写操作继续单独核对密钥。
- 新导出的备份密码至少 6 个字符，恢复已有备份时使用原密码。备份只包含各账号的正式凭据及名称标签、邮箱、保存时间。活动账号、额度快照和待验证的 `.pending` 凭据留在本机。选择重复或凭据含有导入器无法判定的重复字段时，导出会提示修正。
- 账号池、额度身份锁与首次建钥锁（`.vault-key.lock`）统一采用原子目录锁（暂存目录写入唯一持有者令牌文件后原子重命名入位，仅删除自身持有者令牌并以非空保护的 `rmdir` 释放），有界退避回收崩溃残留的空锁、已结束进程及 PID 复用的陈旧锁。
- 仅更改账号名称大小写时，AGS 先记录原名、目标名及中间目录，再移动目录和更新活动引用及标签。进程中断后，下次启动或访问时取得账号池写锁，才会按现场目录恢复。其他进程读取列表时会保留写入中的事务，名称中包含 `.rename-` 的普通账号照常展示。
- 文件权限、身份核对、凭据版本检查和写入失败恢复继续生效。加密不会防住已经控制当前用户会话的进程；使用中的原始凭据仍会短暂存在于内存及官方客户端需要的临时文件。

保存正式账号时，身份、版本和写入内容来自同一次凭据读取。成功写入凭据和元数据后，才清理凭据字节完全相同且只含账号管理文件的自动备份。较新的备份、待验证文件和其他附加内容都会保留。同名卡的身份无法确认或仍有待验证更新时，普通保存会停止。

正式卡和保护备份属于同一身份但持有不同版本时，各自记录所查凭据的额度和下次检查时间。当前卡显示客户端实际登录的额度。池内有待验证凭据时，可在当前卡上选择「更新」重新登录。[额度刷新](refresh-behavior.md)

Antigravity 以账号身份和续期令牌区分同一邮箱的独立登录。跨期刷新与恢复规则见[额度刷新](refresh-behavior.md#antigravity-个人账号)。

Session 导入只对预览中勾选更新的账号暂存替换凭据。预览后的新增身份若已入池，提交时按重复跳过。导入预览、提交和改名使用一致的大小写和 Unicode 等价名称检查。恢复中断的改名时，如目标目录已被占用，会保留已有目录、中间目录和恢复记录。

可信重登替换或删除最后一份同身份账号后，只回收已证实属于旧登录且写入者已结束的恢复文件和临时目录。候选凭据验证并提交账号池后，如仅客户端同步失败，会提示从账号池切换应用该版本。

### 临时副本

独立登录、凭据验证和按访问令牌查询额度使用受管临时目录。备份预览在内存中校验。单项 Session 更新在账号池锁内核对目标后，将候选凭据加密写入该账号的 `.pending`。批量导入的暂存目录与账号池位于同一文件系统，以便原子重命名。创建临时凭据前登记所属进程和随机标记，启动子进程前登记启动状态，POSIX 子进程组用于判断仍在运行的后代。

正常结束会清理；启动时仅回收有合法登记、所属进程和子进程组均已结束的目录。活跃/复用 PID、启动状态不明、符号链接、异常标记、未登记的历史旧目录均保留。Windows 用开机计数和 System 进程创建时间交叉核对重启。旧启动周期中，原所有者已退出且无需写回的已登记目录可回收；同次开机无法确认所有后代均已退出、缺少开机记录或仍待写回时保留。

可能续期的账号查询在启动官方认证前检查系统密钥，确保能写回结果。客户端正在运行或进程状态不明时，AGS 保护桌面和 CLI 正在使用的身份及续期令牌。Codex 和 Antigravity 均可用已有访问令牌做只读额度查询，待验证的凭据替换延后进行。

独立备用账号可由 AGS 续期。Antigravity 在启动可能续期的子进程前，将输入版本加密登记在账号池；子进程组退出、取得可核对的输出后，再加密保存结果。刷新、切换与导出共用恢复检查。官方 CLI 工作目录按目录 `0700`、凭据文件 `0600` 保护，有待恢复的副本保留到结果可确认。
- 对 Codex 的旧导入记录，若没有稳定用户或工作区，显式和自动刷新都须遵守当前客户端的续期限制。允许续期时，用同一份原凭据的官方换票结果补齐身份。普通额度查询和待验证替换都核对登记身份，身份冲突时保留原凭据和登记邮箱。[额度刷新细节](refresh-behavior.md)
- Codex 普通查额优先使用仍有超过一分钟有效期的访问令牌。刷新、切换和导出遇到上次中断的额度查询时，先核对写入进程和私有副本。未轮换可清理，合法轮换写回同版本账号并复读确认。进程仍在写入时等待，身份或工作区冲突时保留恢复副本。
- 查额遇到访问令牌失效时，独立登录可在复核后续期一次，共用登录等待官方客户端。真实续期遭到鉴权拒绝后，可在该账号的详情中查看原因并点击「更新凭据」。

清理失败不覆盖登录、保存或额度查询的结果，尤其不能丢弃已轮换的新凭据。残留受管目录可供下次启动复查。Codex 登录和额度查询共用同一个进程入口，清除 API Key、`CODEX_ACCESS_TOKEN` 与 `CODEX_SQLITE_HOME` 等覆盖变量；Antigravity 继续使用既有系统沙箱隔离。

## 账号移除与客户端退出（已实现）

GUI 为每个选中目标分别保存限时确认。确认期间待验证凭据发生变化，或勾选退出后实时登录已换代，需要重新核对范围。只移除池内副本时，用户的实时登录保留。

1. GUI 先生成删除预览：选中的账号，以及能由相同身份确认的其他备份。显示名称和数量，附属元数据与额度缓存随备份移除。只凭相同邮箱不扩大 Codex 工作区/成员范围。
2. 保留的恢复副本、未知文件、子目录或符号链接会中止移除并留在原处。预览绑定目标、目录实例和完整备份范围，五分钟内有效。目录或凭据内容有变化时需要重新确认。
3. 移除与额度查询共用身份锁，先等进行中的续期完成并写回，再取得短时写锁重新核对。不会直接取消已得到新凭据的查询；后到查询发现记录不存在时不能重建它。
4. 默认只从 AGS 移除，客户端登录、会话历史和项目文件保留。当前账号可显式勾选「同时退出当前客户端登录」；正常退出桌面客户端后，再核对认证存储、共用进程和当前身份，清除已验证的当前凭据。不会删除整个客户端目录或历史数据库。
5. 移除后不维护已删除账号名单。切换遇到未入池的当前账号时必须显式选择是否保存；不保存才不会重新入池。非隔离登录入口遇到未保存的当前身份时先要求保存或在官方客户端退出，不能暗中自动备份回来。
6. 同身份的独立登录副本会取消清理，另一个账号尚未保存的授权会保留。失败会说明已完成的退出/移除数量，其余保留，不能笼统显示全部成功。

| 退出能力 | 当前范围 |
| --- | --- |
| Codex / macOS | 仅显式根级 `cli_auth_credentials_store = "file"`、已知单账号凭据结构、无认证环境覆盖及检测到的管理配置冲突时支持；CLI/IDE 等共用凭据进程须先结束。未知、auto、keyring 和其他结构保留登录并说明原因 |
| Antigravity / macOS | 已有适配的个人账号 Keychain 模式，须先结束共用认证会话；回退文件为空、退出空壳或同身份时一并清理 Keychain、回退文件与超时标记，存在异号或非个人/损坏回退文件时拒绝自动退出 |
| 旧版/未知 Antigravity、其他操作系统 | 尚不启用自动退出，账号池仍可移除；请在官方客户端退出 |

批量移除按同身份预览去重，始终保留客户端登录。CLI `ags rm <agent> <profile>` 先显示范围；加 `--yes` 执行，同步退出须另加 `--logout`，并自行先关闭客户端。

### 历史数据清理辅助

「设置 → 数据清理」当前提供 Codex 通用指令复制按钮。复制不读账号凭据、不维护历史账号名单、不执行删除，提示「已复制，尚未执行清理」。

指令要求用户的 Agent 现场检查版本、目录、认证后端及数据库结构，列出可识别账号，由用户选择目标和范围，再确认具体清单后执行。保护当前登录、共享/归属不明的数据及执行者自身依赖的数据；不把账号不在 AGS 中作为删除依据。找不到线索不等于没有残留。外部导出、浏览器登录、其他设备和服务端授权不在范围内。

### 验证与限制

自动测试使用假 HOME、假账号和进程内测试密钥，覆盖旧明文迁移及失败保留、密文损坏/密钥缺失、导入导出、切换与版本保护、删除范围变更、续期与移除并发、退出时账号变化、临时目录归属和设置复制行为。真实账号池的迁移和删除、Windows 真实用户的端到端流程及 Linux 系统密钥服务仍待验证。

主要实现：`credential-vault.ts`、`temporary-credentials.ts`、`storage-maintenance.ts`、`accounts.ts`、`client-logout.ts` 和 `cleanup-prompt.ts`。

## 应用退出与下载更新（已实现）

GUI 收到退出请求后，会停止接收新的账号写操作和官方共享续期。如已有保存、切换、导入或共享续期在进行，会在退出前等它收尾。已产生的轮换凭据仍可写回。普通只读额度查询不阻塞退出。有未保存登录、待确认导入或未完成下载时，AGS 会说明将取消的范围，用户可以继续使用。

已发布的 1.0.1 支持在 macOS 应用内下载 DMG，Windows 用户从发布页下载。当前源码在 Windows x64 和具备替换权限的 macOS 安装位置支持一键安装并重启。退出前沿用账号写入与凭据续期的安全检查。版本状态在设置中展示。[应用内下载更新](app-updates.md)

## 后续调整方向（尚未实现）

AGS 的目标是账号能保存和再次使用、切换尽量少操作，并能查看可获取的额度。通用流程以现有代码为起点，随实际场景完善；不以任何单个平台当前实现为完整标准。

- 继续共用账号池和切换调度；平台适配负责取得、读取和应用认证状态、续期、客户端生效方式及额度获取。
- 调度按平台需要执行步骤：支持运行时切换时可省去重启，必须重新加载时复用现有退出与重开工具；步骤不要求各建一个模块。
- 接入新的存储或第二种额度来源时，按实际差异调整现有接口和 Codex 分支；不复制整套管理流程，也不预先搭建通用插件框架。
- 切换结果采用平台能可靠提供的依据；已有本地检查优先复用，新增运行时确认、重试或恢复须解决具体问题。额度失败单独展示，避免阻塞已经完成的切换。

| 平台 | 下一步需补齐或验证的部分 |
| --- | --- |
| Codex | 保持现有文件账号完整流程；遇到其他认证存储或客户端生效需求时补相应适配，不把当前流程冻结为标准 |
| Antigravity | 已接入 macOS 个人账号的独立添加、保存、切换和额度查询。当前账号闲置跨期刷新的通过条件见第 05 问，企业认证保留待验证 |

具体认证机制依据官方资料及原型结果确定；以下区分官方文档依据、本机兼容适配及实际验证范围。

## Antigravity 当前实现与验证

目标是用户主动选择账号后直接继续使用官方客户端。日常切换复用已有锁、凭据备份、版本检查、桌面退出与重开，不加入额外联网验收。桌面重开失败只提示手动启动；额度失败单独显示历史数据。

### 官方入口与本机适配

- [官方认证说明](https://antigravity.google/docs/install/)：App、CLI、IDE 共用个人账号认证；因此单独修改子进程 `HOME` 不能隔离 Keychain。
- [官方 ACP](https://antigravity.google/docs/ide/extensions/acp)：使用 `agy acp` 的 `initialize`、`authenticate`，由官方 CLI 完成 Google 浏览器授权和续期；AGS 不实现 OAuth 交换。
- [官方 `/usage`](https://antigravity.google/docs/cli/commands/usage/) 与 [CLI 更新记录](https://antigravity.google/docs/changelog?tab=cli)：使用 `agy -p /usage --output-format json` 获取后端额度，无模型对话；套餐取 ACP 认证结果。
- 桌面与 CLI 共用个人账号 Keychain 项 `gemini / antigravity`。小凭据通过标准输入更新并回读，写入命令须短于 4,000 字节。该限制也用于判断旧值能否安全回滚。[Apple 命令行工具实现](https://github.com/apple-oss-distributions/Security/blob/main/SecurityTool/macOS/security.c)
- AGS 识别官方客户端内切换的账号时，先确认匹配项唯一、所属钥匙串已解锁，再禁用交互读取。若当前条目仅允许系统工具读取，AGS 核对已有授权，调用工具取值，并在使用结果前再次核对条目版本。桌面状态和共享额度查询采用同一套判断。
- 显式切换时，目标过长、原钥匙串值过长或旧条目仅能由原 AGS 读取时，可使用下面两个官方登录文件。若原来使用钥匙串，或首次使用文件存储，桌面会先说明凭据将存为两个权限为 `0600` 的本机文件。CLI 需要加 `--allow-file-storage`。已有文件登录可直接继续使用文件。旧版留下的空项和已识别编码内的残缺凭据也可经确认恢复。企业或无法识别编码的条目仍保留原件。
- AGS 先加密记录原状态，再分别写入并核对两个文件的完整内容和权限。活动账号标记保存成功后才尝试移除原个人钥匙串项。此后桌面与 CLI 即使没有超时标记也各自读到目标文件。失败时会核对现状，仅撤销本次仍可确认的变更；若进程被强制结束，下次主动切换时会先核对恢复记录。外部换号或退出时保留现场。当前账号的新授权或隔离续期超过钥匙串写入上限时，客户端空闲可按事务迁移到双文件。客户端仍占用登录时，先保存新凭据到账号池并提示切换应用。下次启动会在首屏提示中断的切换。若桌面和 CLI 同时使用文件登录，两份属于原续期会话的文件都会得到新凭据，同邮箱的独立续期会话保留原件。
- 官方桌面端与 CLI 的文件认证回退分别为 `~/.gemini/jetski-standalone-oauth-token`、`~/.gemini/antigravity-cli/antigravity-oauth-token`（读写与清理前均校验父目录非符号链接），对应 1 小时超时标记 `~/.gemini/cache/antigravity-keyring-unavailable`、`~/.gemini/antigravity-cli/cache/antigravity-keyring-unavailable`。AGS 按真实优先级解析当前生效账号：桌面端存在活跃超时标记且桌面回退文件含有效个人凭据时取桌面回退（此时被遮蔽的异号 Keychain 同样纳入附属凭据保护，后台续期更新属于同一续期会话的既有回退文件，保留异号 Keychain）；否则 Keychain 含有效个人凭据时以 Keychain 为主；Keychain 为空时接受单一文件，或以账号身份及非空续期令牌相同确认两份文件属于同一会话。优先选择含可用访问令牌的完整副本，再比较可用时间。同邮箱的不同续期令牌须保留，无法确认来源时提示冲突。切换前先逐源比较凭据版本再按身份归组，确认指纹同时绑定全部凭据来源与标记生效状态并在首次写入前最终重检；前置检查失败零写入零回滚，发生部分写入后仅按变更记录逆序回滚本次 AGS 改动且此后未被外部修改或退出的来源（回滚自身失败时明确说明失败步骤与已保留状态）。
- 独立 CLI 的文件认证回退在临时 `HOME/.gemini/antigravity-cli/antigravity-oauth-token`。该路径和 Keychain 编码是本机验证的兼容细节，不是官方承诺不变的公共接口。

### 添加与切换

当前源码中，点击 macOS 右上角 AGS 图标即可看到当前账号额度和可切换的备用账号。点选名单中的目标即执行切换。遇到未保存登录或需退出客户端等情况时，沿用主窗口的切换确认流程。[菜单说明](navigation-menus.md)

| 用户操作 | AGS 流程 | 对当前登录的影响 |
| --- | --- | --- |
| 保存当前账号 | 按上述优先级读取当前生效身份与凭据，沿用账号池去重、命名及备份 | 不改变 |
| 添加其他账号 | 独立临时目录运行官方 ACP，捕获官方浏览器 URL；普通/无痕/复制链接共用同一次会话；完成后读取并保存官方生成的凭据 | 不退出、不替换当前登录；取消时结束子进程并清理目录 |
| 切换账号 | 同步当前账号及回退文件中已入池的更新版本，对未入池的当前/回退个人账号走显式保存或丢弃确认；按上文的权限与长度约束更新并校验目标来源，清理已确认可移除的旧文件（失败时仅撤销本次写入且之后未变化的来源，保留官方端的新登录或退出），再重开原桌面并异步刷新额度 | 切换至目标账号，无须重复浏览器登录 |
| 凭据失效 | 既有「更新」入口独立重新授权，核对目标身份后原位更新；后台续期与原位写回仅清理退出空壳或同身份回退文件，不误删异号回退凭据 | 只在当前仍使用同一份失效凭据时同步替换，保留账号名称 |

添加账号、独立备用账号续期和按访问令牌查询额度使用独立 `HOME`、工作目录和临时目录。macOS sandbox 拒绝这些子进程访问真实认证目录、Keychain 和浏览器，只允许写入本次临时目录。AGS 清除认证覆盖变量，官方 CLI 使用自己的文件回退。请求官方端更新当前共享登录时，CLI 使用官方原有的 `HOME` 和独立工作目录，并限制浏览器启动。

添加账号时，临时 `open` 辅助程序把官方登录链接交给 AGS，再由现有浏览器入口打开。额度查询中的 `/usage` 若转入浏览器登录提示，AGS 会结束查询进程，详情提示确认登录状态。网络故障也可能触发这条提示，原账号和上次额度继续保留。

普通登录与无痕入口共用同一次授权会话。无痕入口支持 Google 与 OpenAI 官方登录域名，复用 Chrome / Chromium、Edge、Brave、Arc、Vivaldi、Firefox 的私密窗口参数；Safari、其他未适配浏览器、启动失败或关闭自动打开设置时复制同一链接，供用户在本机私密窗口粘贴。链接约 15 分钟过期；完成授权后须回到 AGS 核对账号并保存，关闭添加窗口会取消未保存会话。

App、CLI、IDE 共用认证。日常切换检测其他正在运行的共用会话，提示用户先结束；GUI 与命令行会核对 AGS 临时目录的进程组记录和进程工作目录，识别另一 AGS 进程启动的隔离查询及其子进程。无法确认归属时保留会话保护。不强退无关编辑器或终端。

### 当前账号与备用额度

当前登录可在同一会话的有效令牌上查额度。备用账号的独立续期和中断恢复共用身份锁。macOS 官方共享登录的判定、查询结果归属和重试条件统一维护在[额度刷新](refresh-behavior.md#antigravity-个人账号)。

GUI 以 Gemini 作为主额度和默认排序依据；当前卡片直接显示其实际周期，其余模型组按内容长度自然排列。备用卡片与单行只保留 Claude / GPT 摘要（窄卡简称 C/G），Argon 等组通过原有右键详情查看；Pro 与 Ultra 不强行补齐模型桶。没有返回的比例保持未知，不将其他组当作 Gemini，不展示平台未提供的 Credits。

当前支持 macOS 个人账号的 Keychain 与官方桌面、CLI 文件登录。遇到企业或未知认证时保留现有登录。需要安装官方 `agy`，官方格式或系统 sandbox 能力变化可能需要适配。登录、保存、切换和额度已接入 GUI。已完成的隔离测试及仍需真实账号验证的流程见[当前待办](当前待办.md)。

## Antigravity 账号管理闭环与十四问（设计与验收）

范围为 macOS 上 AGS 已适配的 Antigravity 个人账号。用户在官方客户端使用 A，把 B 加入 AGS，随时看两者的额度，切到 B 后还能切回 A。归档、迁机和移除沿用这两份账号记录。主窗口、菜单和 CLI 共用规则，入口只决定用户要做什么，以及此时能否请用户确认。

### 一条操作流程

**定位账号 → 核对当前登录和池内版本 → 处理该登录上次未完成的写回 → 执行本次操作 → 核对结果并记录。** 打开页面优先显示已有资料。需要使用、替换或带走凭据时才做相应检查。每次操作只请求所需的权限，切换和导出有可确认的本地凭据时可以离线完成。

“当前”和“备用”是账号此刻的角色。账号池保存已确认的登录版本。官方端决定当前生效的身份。额度是官方在某个时间返回的观测值。这三项可以各自变化，查询失败不会把账号改成未登录，访问令牌过期也不会把剩余额度改成零。

当前账号只需一次官方登录。Antigravity 和 AGS 用这次登录查各自需要的信息。官方续期产生的新令牌仍属于这次登录。普通额度查询全程使用这次登录，已有账号和未保存的当前账号适用同一规则。

以“切到 B”为例。AGS 先保护当前 A，再确定 B 可以交给客户端的凭据版本。B 上次续期留下了可确认的新凭据，就先写回、回读，再执行切换。若重开客户端失败，用户看到的是“B 已写入，客户端待打开”。若随后查额度超时，B 仍是已经写入的账号，最后一次成功额度仍有自己的时间。

| 核对后的事实 | 本次可以做什么 | 怎样回到正常使用 |
| --- | --- | --- |
| 身份及登录版本可确认 | 按该登录的归属查额度、切换或导出。续期只由有权使用它的一方发起 | 成功后记录取到的额度或实际提交的凭据版本 |
| 同一次登录有可确认的新凭据尚未写回 | 先完成写回并回读，再继续用户原来的操作 | 下次从任一入口进来都会读到同一版 |
| 已经发起过续期，结果不明 | 保留副本。仍有效的访问令牌可以查额度。暂停使用可疑旧凭据续期、切换或导出 | 找到可信后继，或通过官方登录取得已验证的替代凭据，再续办原操作 |
| 暂时拿不到额度 | 保留上次额度和成功时间。网络、服务和限流按原因退避。当前登录需要续期时先核对官方来源 | 已核实属于同一共享登录时在本次刷新请求官方续期一次。其他登录出现可用的新令牌或到达重试时间再查 |

### 七轮反问与回答

依据《让 AI 用经典理论反问的思考方法》，用第一性原理确定每一步要交付什么，再用失效模式分析逐步追问“上一步的答案在什么情况下会失效”。以下是设计自审。每题的验收条件都可以用一个反例推翻。

**第一轮 · 账号与身份**

**01　怎样才算 AGS 真正管理住了一个账号？** A 在官方端工作时能保存 A、加入 B。切到 B 再切回 A 后，官方端分别认出 B 和 A，两个账号的额度历史各归其主。桌面当前使用谁由官方登录的可确认信息决定。保存、刷新和导出都不隐含切换。

*通过条件*　从 A 开始走一圈，分别核对官方端的身份、AGS 昵称和最近一次额度来源。只改了卡片标记仍算失败。

**02　同一个邮箱出现两次，凭什么能合并？** 昵称是用户标签，账号身份用官方可核对的标识，登录凭据还要区分来源和版本。规范化邮箱可用来找到已有卡片。同账号的另一份登录单独核对。外部文件先按现有导入规则预览，只有可信身份和本次目标相符才允许替换。重复导入复用原卡，保留已有的独立保护副本。
外部文件中的明文邮箱或自报身份只能用于预览。候选凭据在隔离环境经官方认证并核对目标身份后才能取代原登录。官方额度响应未带账号时，查询必须绑定这份已确认的凭据，且隔离环境没有其他可用登录。

*通过条件*　同一个 B 再导入不多出普通账号卡。把 A 的邮箱与 B 的凭据放进候选文件，原 A、B 及当前登录均保持原状。

**第二轮 · 加入与登录归属**

**03　A 正开着工作，加入 B 会把 A 挤掉吗？** 保存当前只把可确认的 A 存入账号池。添加 B 在隔离目录完成官方登录，回调后展示实际身份并保存 B。改名沿用同一账号记录。切走前若发现未保存的 A 或其他独立登录，沿用现有的保存、明确丢弃、取消选择。

*通过条件*　分别从官方登录、保存当前、文件导入进入。取消添加 B 后没有半成品卡片。完成添加 B 后官方端仍能以 A 工作。

**04　A 和 B 都能查额度，谁有权使用续期令牌？** 归属跟着每一份登录走。客户端正在使用或可能使用的登录由官方端续期。AGS 可用其有效访问令牌查询。AGS 独立持有的登录可以在隔离目录续期。切换时重新核对实际主登录和回退来源。B 变成当前账号后立即受到共享登录保护。
交接需要可复核的事实。例如在切换 A 到 B 时，原持有 A 的客户端已退出，B 已写入并回读，其他共用来源也已解除对 A 的引用，此时 AGS 可将保存的 A 转为备用。一次进程扫描显示桌面已退出，无法证明它下一刻不会重开；无法证明独占的登录仍按共享处理。AGS 发起的切换须等同一登录已开始的续期安全收尾，其他账号仍可操作。

*通过条件*　把 B 切为当前时，先前排队的备用刷新重新检查归属。加一个相反的时序，让官方端在进程检查后立即重开，共享续期令牌仍由官方端使用。

**第三轮 · 当前账号跨期与人工确认**

**05　Antigravity 一直开着，A 的访问令牌到期后，「刷新」到底做什么？** AGS 先用 A 同一次登录的可用令牌。macOS 官方钥匙串或安全双文件满足归属条件时，调用一次官方共享 `/usage`，回读确认仍是 A 的同一份授权后使用返回的额度。无法确认时保留上次成功时间。本机共享钥匙串的历史跨期结果见[当前待办](当前待办.md)。

*通过条件*　A 只登录一次，桌面打开并闲置到访问令牌自然到期，直接点 AGS「刷新」就取得 A 的新额度响应。全过程无需操作官方端、退出或再次授权；再跨一次自然到期，AGS 仍能查，官方端也仍能正常使用。本机已在同一桌面进程中从普通刷新入口取得两次真实的新额度。

**06　什么时候才需要用户再次登录？** 账号详情沿用「刷新额度」，顶栏沿用「刷新全部」。只有官方明确表示原登录已失效并需用户认证，单账号手动操作才可接续现有登录流程。用户同意后核对实际身份，更新原账号，再继续原查询。未保存的当前账号也能查询，加入账号池由用户单独决定。批量、后台和非交互 CLI 仅返回需处理的账号及原因。

*通过条件*　访问令牌到期、一次查询被拒、断网或限流都不会自行打开登录页。另用已明确失效的登录验证重新登录流程，选错账号或取消时保留原记录。普通查询没有独立授权按钮。

**第四轮 · 并发与断电**

**07　菜单、主窗口和 CLI 同时刷新 A，期间用户又在官方端换成 B，会怎样？** 同账号、同一登录版本的请求合并或复用，沿用 30 秒最短检查间隔。耗时的网络或浏览器操作在账号池写锁之外进行。提交前重新核对账号、登录版本、归属和本次用途。迟到的结果只能写回仍匹配的 A。可信新版本到达后清除旧的等待与授权提示。
官方端完成续期后，按该登录已确认的新版本结束旧的等待和冷却，合并并发点击并实际查询一次。同一份旧凭据仍处于等待时，重复点击只返回已有结果。

*通过条件*　三处同时触发只产生一次同版本的外部查询。换成 B 后收到 A 的响应，B 的凭据、额度、成功时间均不变。A 已移除时，迟到的响应不能把 A 建回来。

**08　服务端已经换票，AGS 还没来得及写回就崩溃，重启靠什么判断？** 有可能换票前，先在受保护的账号存储记录身份、用途和输入版本。记录无法持久化就暂停换票。拿到同一登录的新凭据后加密暂存，核对原版本，写回并回读，最后才清理待决记录。只读额度查询无需建立这份记录。
续期成功、随后的额度查询失败时，先确认新凭据已保存，再显示额度查询失败。用户取消或 AGS 退出时同样要收尾已经产生的新凭据。重试额度请求只使用已确认的版本。

*通过条件*　在发请求前、发出后未收到结果、写回后未清理三个位置中断。可证明未发出的操作能重试，已提交的可以收尾。结果不明时保留证据。系统清理临时目录后，池内待决记录仍能阻止旧票重放。

**第五轮 · 恢复与切换**

**09　旧版本留下的恢复副本，哪些能自动救，哪些必须停？** 在账号锁下核对来源、身份、输入版本、输出和写入者。能证明属于同一登录的后继才采纳。旧标记不足、已发送但只剩原件，或多个副本互相矛盾时，保留现场，仅用仍有效的访问令牌查额度。旧版现场已经丢失时，AGS 无法重建那次服务端结果。

*通过条件*　同一可恢复现场分别以刷新、切换、导出作为第一步，三个入口采用同一后继。无法证明的现场中，旧票重放次数为零。需要替换登录时，沿既有官方登录流程核对同账号，取消后仍可回来处理。

**10　A 切到 B，何时可以告诉用户切换成功？** 先保护 A、确认 B 的版本和当前生效来源，再按已有平台能力处理共用进程、长凭据和文件回退。只关闭切换确实需要退出的客户端，回读目标存储后重开原桌面。分别报告“已写入 B”“客户端已重开”和能可靠确认的实际身份。没有运行时身份依据时，界面只报告已经证实的步骤。
在退出桌面前尽量完成目标和存储预检。钥匙串拒绝访问、存储格式未知或另有共用进程时，指出阻塞原因。后台停止触发授权或钥匙串弹窗。若用户已同意关闭桌面但切换失败，尝试重开此前运行的桌面并告知最终状态。

*通过条件*　离线可完成本地切换。查额度失败不会撤销已成功的切换。任一写入失败，只撤销仍属于本次操作的改动。外部已换号或退出时保留其选择。真机往返须在桌面及 CLI 均核对 A、B。

**第六轮 · 迁机与退出**

**11　今天导出的 B，明天还原时能拿到哪一版？** 导出复用与切换相同的版本检查，打包该时点已确认的账号登录。活动账号标记、历史预览遗留的授权文件和恢复记录留在本机。所选账号有未解决项时指出具体账号，保留原备份，用户可重新选择健康账号导出。还原先预览、去重，保护本机更新的登录。旧备份本身不能保证其中的票据至今仍有效。

*通过条件*　取得一份可恢复的 B 后，直接导出，在空池解密还原，得到已确认的新版本。导回已有较新 B 的池不会覆盖它。迁机实测时结束原机对该登录的使用，避免两台机器同时续期。

**12　“从 AGS 移除”和“退出官方客户端”怎样收尾？** 默认移除只处理预览中选定的池记录及缓存。待恢复副本可能是唯一的新登录，单列说明并在明确处置前保留。显式勾选退出客户端后才校验当前登录身份并退出。账号已经变更时重新确认。迟到的授权回调随原操作取消。

*通过条件*　移除备用 B 后，官方 A 继续工作。仅移除当前 A 后，官方 A 仍登录。显式退出遇到外部换号时，新账号保持登录。移除、登出各自报告已完成的范围。

**第七轮 · 证据与验收**

**13　数字没变、一直转圈、提示要登录，维护者怎样知道现场发生了什么？** 每次检查都区分本地检查时间与最近成功取得官方额度的时间。记录账号匿名编号、操作来源、版本是否变化、恢复判断原因、是否实际查询或续期、官方错误类别及提交结果。相同等待合并。按官方限流期限或已有退避重试。故障报告只导出脱敏事件。
请求超时、取消、命中缓存和返回等待都要结束本轮转圈。报告区分“有写入者”“缺少或冲突的结果”“已经写回”和“存储不可用”，无需用户自己填写故障原因。官方结果无法分类时保留“原因未明”，避免误导用户再次登录。

*通过条件*　用同一网络故障分别查询带与不带到期时间的令牌，均报告网络故障。后台重复等待时外部换票次数为零。官方新响应即使余额相同也更新成功时间。缓存命中只显示上次成功时间。报告不含邮箱、令牌、授权链接或本机路径。

**14　什么证据会推翻“整个闭环已经通过”？** 验收看三个真实结果。官方客户端仍能使用正确的账号。当前账号只登录一次，桌面闲置跨期后点刷新能取得新的官方额度响应。备用账号切换、导出及还原使用同一份已确认的登录。依赖另一份授权、用户先去官方端操作，或要求先刷新才能安全切换、导出，均判对应项目未通过。

*通过条件*　在独立 macOS 用户中，用 A、B 两个获授权的个人测试账号完成第 05、10 问的真机流程。用可重复的隔离现场完成第 09、11 问的顺序对照，再验证结果不明、取消和网络故障。保留脱敏的查询、版本和身份核对结果。主窗口、菜单、CLI 共用同一套结论。

### 评审结论与最小验证顺序

- **已完成隔离验证。** 备用账号有可确认的新凭据时，从刷新、切换或导出开始都会先恢复同一后继。已验证导出再导入空池得到同一版本，原输入的可读同版本副本随之更新，其他独立登录保持各自版本。[三个入口的回归用例](../tests/antigravity-quota-recovery.test.cjs)
- **当前账号已完成隔离验收。** 隔离测试核对共享查询前后属于同一次登录，遇到身份或授权变化即中止写回。用例同时覆盖查询中同邮箱重新登录、无到期时间的令牌被拒、网络或限流时不再请求续期，以及连续点击复用最近结果。[额度回归用例](../tests/antigravity-cli.test.cjs)
- **官方 CLI 已接入普通刷新。** 官方支持用本机个人登录执行 `/usage`。AGS 对共享钥匙串和官方双文件的归属核验见[当前账号与备用额度](#当前账号与备用额度)。[Google 认证说明](https://antigravity.google/docs/install?tab=cli) · [官方命令参考](https://antigravity.google/docs/cli/reference/)
- **最小验证。** 独立 macOS 测试用户只登录 A 一次，先确认到期前的官方查询成功。桌面保持打开并闲置到自然到期，此时先点 AGS 刷新。若失败，在官方端执行一次需要认证的正常操作后再查，对照同一登录的版本是否变化、AGS 是否读到、官方查询是否成功。只有后一次成功，只能登记为“可跟随官方续期”。本机已有登录于 2026-11-21 完成连续两轮直接刷新。独立用户的双账号往返另行验收。
- **真实客户端验收。** 在独立 macOS 用户中完成 A → B → A，两次分别核对官方桌面和 CLI 身份，再检验迁机备份和移除。十四问的通过条件沿用同一标准。[本轮待办](当前待办.md)

账号操作层共用已有的身份锁、版本比较和回读。Antigravity 适配器负责官方登录来源、额度查询和客户端生效方式。旧源码预览可能留下额外额度授权的加密文件。当前源码保留原件，普通刷新、切换和迁机备份只使用账号本身的登录。
