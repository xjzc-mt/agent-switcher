# 账号管理流程

本页记录截至 2026-11-20 的 1.0.1 候选源码行为与后续方案。当前的平台范围和升级说明见[候选版说明](release-1.0.1.md)。

当前平台为 Codex（`codex`）、Claude Code（`claude`）、Antigravity（`agy`）。项目没有单独的 Gemini CLI 适配器，讨论 Gemini 时需明确是否指 Antigravity。

首版 GUI 按 Codex、Antigravity、Claude Code 排列。Claude Code 置灰放最后并显示开发中提示，添加入口禁用；下表 Claude Code 行仅说明保留的底层实现，不表示首版 GUI 开放这些功能。

## 当前共同流程

1. 添加账号：通过平台登录入口取得凭据，或导入已有凭据，再保存到账号池。是否改变当前客户端登录取决于平台，见下表。
2. 管理账号：账号池复用保存、身份去重、改名、删除、导入与导出；保存或导入成功不代表已切换客户端。
3. GUI 切换：先判断当前适配器是否支持；若对应桌面客户端正在运行，提示用户完成或停止任务，确认后正常退出。客户端原本未运行时不自动启动。
4. 应用账号：`useAccount` 同步当前已入池凭据，再调用平台的 `use` 应用目标凭据。当前身份未入池时，GUI 先明确选择「保存后切换」或「不保存并切换」；CLI 使用 `--save-current` 或 `--discard-current`。保留凭据版本检查和写入失败恢复。
5. 更新界面：重开此前退出的客户端，显示切换结果并更新账号列表；Codex 与受支持的 Antigravity 随后按缓存规则查询额度，额度查询不作为切换成功的前置条件。
6. CLI 切换：`ags use` 调用同一个 `useAccount`，检测到对应桌面客户端仍运行时要求先退出，不执行 GUI 的退出与重开操作。已有终端会话需自行重开。

当前“已切换”表示本地凭据已应用并通过写入结果检查；没有重开后读取桌面实际账号的步骤。重开失败会提示手动启动，不撤销已经完成的凭据切换。移除默认保留客户端登录；当前账号可在支持的认证存储下显式选择退出并移除，见下文。

### Windows 候选源码

Windows 的 Codex 文件认证、独立登录和额度查询共用官方 CLI 查找。已有桌面、CLI 或 IDE 使用登录时，结束相关会话后再切换。系统凭据库、组织限制等无法按文件处理的环境会在写入前提示原因。Windows 独立测试用户的端到端验收仍待完成。[Codex 认证存储](https://developers.openai.com/codex/auth/)

新建或改名时统一检查 Windows 保留名、非法字符和尾点。旧 macOS/Linux 账号仍可使用并改名；旧备份中的不兼容名称可在导入预览中修正，再确认恢复。[Windows 文件命名](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)

### 本地故障报告

桌面端自动保留最近 7 天内的有限操作记录。记录包含 AGS 版本、系统平台、操作来源、相对耗时和预定义的步骤及结果，按数量滚动并优先保留故障现场。源码预览会在版本号后附上应用代码摘要，方便区分同版本的不同修改。记录中的账号标识在导出时换成报告内编号。额度查询可区分缓存、只读和实际启动查询等路径。刷新没有取得新额度时，沿用已知的上次成功时间。

「设置 → 应用与更新 → 导出故障报告」只读取已有记录，将脱敏 JSON 保存到用户选择的文件。导出后可私下交给维护者。邮箱、账号原名、凭据、完整路径、命令参数及 CLI 原始输出均不进入报告。

## 凭据安全与迁移（已实现）

- 账号池中的 Codex、Claude Code、Antigravity 凭据，以及池内导入暂存凭据，使用 AES-256-GCM 加密；凭据格式与平台作为认证附加数据。昵称、额度快照等元数据保持原格式，客户端使用的原生凭据文件/Keychain 也保持官方格式。
- GUI 启动及 CLI 操作前在账号池锁内迁移旧明文文件：先写加密临时副本、从磁盘回读并解密比对，再核对原文件未变化，最后原子替换。逐文件完成，失败不会删除对应原件；已经成功迁移的文件仍可使用。损坏的密文、丢失或不匹配的密钥不会触发覆盖或重新生成密钥。
- macOS 主密钥由 Keychain 保管，GUI 与 CLI 共用；密钥通过标准输入写入，不进入进程参数或账号池。Windows 使用 CurrentUser DPAPI 包装密钥，Linux 使用 Secret Service（`secret-tool`）；后两者代码分支尚未做对应操作系统的真实环境验收。系统存储不可用时拒绝新的凭据写入，不静默回退成明文。
- 本机加密文件依赖系统密钥，迁移机器使用现有 `.ags` 密码加密导出/导入，不直接复制账号池目录。新导出的加密备份使用显式 `AGS2` 版本头（密码做 Unicode NFC 归一化，头部附带受 GCM 认证的有界 `scrypt` 参数 `N=65536, r=8, p=1`），导出端统一校验单文件与 `_meta.json` 上限、解压总体积及最终加密包体积上限（确保导出成功的备份同版必可导入），导入端在分配解压条目对象前按实际解包器同一目录范围校验非分卷/非 ZIP64 布局、中央目录条目数上限与声明体积；当前版本兼容恢复旧 `AGS1` 备份及超过 200 个账号的历史大备份，但旧版（如 v1.0.0）无法直接解密新版导出的 `AGS2` 备份文件。
- 当前进程缓存已成功解锁的读取密钥，避免每次刷新界面访问系统密钥服务；重启后重新获取。启动扫描已加密文件时，整批读取一次系统密钥，即使首批文件全部损坏也逐卡报告；单个凭据写入及旧明文迁移在替换原件前重新读取系统密钥并校验落盘内容。凭据损坏、目录名异常或凭据路径被替换为目录或符号链接时，面板和 CLI 标记相应账号，健康账号仍可操作。密钥丢失或替换时停止写入，当前仍已解锁的账号可先导出恢复备份。旧版本不能直接读取迁移后的加密账号池，降级前须用目标版本兼容方式准备凭据。
- 批量导入在同一把账号池写锁内准备新增账号和待验证更新，每份暂存密文都读回解密并与输入核对。已建钥的正常批次在开始、准备完毕及提交结束时各核对一次系统密钥。macOS 把这三次核对和首次建钥交给工作线程，等待系统服务时主线程仍可处理界面事件。发现换钥或丢钥会撤销本批变更，其他写操作继续单独核对密钥。
- 备份只包含各账号的正式凭据及名称标签、邮箱、保存时间。活动账号、额度快照和待验证的 `.pending` 凭据留在本机。选择重复或凭据含有导入器无法判定的重复字段时，导出会提示修正。
- 账号池、额度身份锁与首次建钥锁（`.vault-key.lock`）统一采用原子目录锁（暂存目录写入唯一持有者令牌文件后原子重命名入位，仅删除自身持有者令牌并以非空保护的 `rmdir` 释放），有界退避回收崩溃残留的空锁、已结束进程及 PID 复用的陈旧锁。
- 仅更改账号名称大小写时，AGS 先记录原名、目标名及中间目录，再移动目录和更新活动引用及标签。进程中断后，下次启动或访问时取得账号池写锁，才会按现场目录恢复。其他进程读取列表时会保留写入中的事务，名称中包含 `.rename-` 的普通账号照常展示。
- 文件权限、身份核对、凭据版本检查和写入失败恢复继续生效。加密不会防住已经控制当前用户会话的进程；使用中的原始凭据仍会短暂存在于内存及官方客户端需要的临时文件。

保存正式账号时，身份、版本和写入内容来自同一次凭据读取。成功写入凭据和元数据后，才清理凭据字节完全相同且只含账号管理文件的自动备份。较新的备份、待验证文件和其他附加内容都会保留。同名卡的身份无法确认或仍有待验证更新时，普通保存会停止。

正式卡和保护备份属于同一身份但持有不同版本时，各自记录所查凭据的额度和下次检查时间。当前卡显示客户端实际登录的额度。池内有待验证凭据时，可在当前卡上选择「更新」重新登录。[额度刷新](refresh-behavior.md)

Antigravity 官方客户端运行期间，AGS 可用同一登录的有效访问令牌只读查询当前账号额度。暂时无法查询时，用户可以继续使用客户端。客户端更新登录信息后，AGS 会在下次刷新时重查额度。独立登录的凭据版本不一致时，详情会说明版本差异。

Session 导入只对预览中勾选更新的账号暂存替换凭据。预览后的新增身份若已入池，提交时按重复跳过。导入预览、提交和改名使用一致的大小写和 Unicode 等价名称检查。恢复中断的改名时，如目标目录已被占用，会保留已有目录、中间目录和恢复记录。

### 临时副本

独立登录和需要运行官方 CLI 的验证、额度查询使用受管临时目录。备份预览在内存中校验；单项 Session 更新在账号池锁内核对目标后，将内存中的候选凭据加密写入该账号的 `.pending`。批量导入的安装暂存留在账号池所在文件系统，以便原子重命名。创建临时凭据前登记所属进程和随机标记，启动子进程前登记启动状态，POSIX 子进程组用于判断仍在运行的后代。

正常结束会清理；启动时仅回收有合法登记、所属进程和子进程组均已结束的目录。活跃/复用 PID、启动状态不明、符号链接、异常标记、未登记的历史旧目录均保留。Windows 用开机计数和 System 进程创建时间交叉核对重启。旧启动周期中，原所有者已退出且无需写回的已登记目录可回收；同次开机无法确认所有后代均已退出、缺少开机记录或仍待写回时保留。

池账号真正发起额度查询前重新检查系统密钥，无法写回时不启动续期；仅返回有效缓存时不需要此检查。官方客户端正在运行或无法可靠确认其运行状态时，普通刷新与待验证凭据更新均在启动认证前判定：凡池内凭据与桌面主来源、CLI 回退来源身份相同，或两者持有同一份续期令牌，都走保证不轮换的查询路径（Codex 仅在访问令牌未过期时剥离真实 `refresh_token` 以只读副本查询且不写回实时目录，Antigravity 将仍有效的访问令牌单独交给隔离的官方 `/usage`，访问令牌到期时等待客户端续期，待验证更新延后等待客户端关闭）；官方端自行续期后自动同步回池，备用账号仍独立续期。查询开始前登记待提交状态，子进程关闭后排空整个进程组再回收目录；重试或验证分支仅在确认对应轮换代际已安全持久化、或确有经服务端续期产生并落盘的后继凭据时才清理旧临时副本，其余缓存命中、仅凭访问令牌读到额度但未续期、轮换后额度请求失败、认证过期、提交冲突或抛错路径均保留恢复目录并在结果中附上路径。恢复前须核对身份与版本，不自动覆盖新登录。这些官方格式临时凭据仍受目录 `0700` / 文件 `0600` 保护，不能当作已清除的历史残留。
- 对 Codex 的旧导入记录，若没有稳定用户或工作区，显式和自动刷新都须遵守当前客户端的续期限制。允许续期时，用同一份原凭据的官方换票结果补齐身份。普通额度查询和待验证替换都核对登记身份，身份冲突时保留原凭据和登记邮箱。[额度刷新细节](refresh-behavior.md)

清理失败不覆盖登录、保存或额度查询的结果，尤其不能丢弃已轮换的新凭据。残留受管目录可供下次启动复查。Codex 登录和额度查询共用同一个进程入口，清除 API Key、`CODEX_ACCESS_TOKEN` 与 `CODEX_SQLITE_HOME` 等覆盖变量；Antigravity 继续使用既有系统沙箱隔离。

## 账号移除与客户端退出（已实现）

GUI 为每个选中目标分别保存限时确认。确认期间待验证凭据发生变化，或勾选退出后实时登录已换代，需要重新核对范围。只移除池内副本时，用户的实时登录保留。

1. GUI 先生成删除预览：选中的账号，以及能由相同身份确认的其他备份。显示名称和数量，附属元数据与额度缓存随备份移除。只凭相同邮箱不扩大 Codex 工作区/成员范围。
2. 删除凭据文件之外出现未知文件、子目录或符号链接时保留并报错。预览绑定目标、目录实例和完整备份范围，五分钟失效；重建目录、重命名或增加副本后需要重新核对。
3. 移除与额度查询共用身份锁，先等进行中的续期完成并写回，再取得短时写锁重新核对。不会直接取消已得到新凭据的查询；后到查询发现记录不存在时不能重建它。
4. 默认只从 AGS 移除，客户端登录、会话历史和项目文件保留。当前账号可显式勾选「同时退出当前客户端登录」；正常退出桌面客户端后，再核对认证存储、共用进程和当前身份，清除已验证的当前凭据。不会删除整个客户端目录或历史数据库。
5. 移除后不维护已删除账号名单。切换遇到未入池的当前账号时必须显式选择是否保存；不保存才不会重新入池。非隔离登录入口遇到未保存的当前身份时先要求保存或在官方客户端退出，不能暗中自动备份回来。
6. 同身份的独立登录副本会取消清理，另一个账号尚未保存的授权会保留。失败会说明已完成的退出/移除数量，其余保留，不能笼统显示全部成功。

| 退出能力 | 当前范围 |
| --- | --- |
| Codex / macOS | 仅显式根级 `cli_auth_credentials_store = "file"`、已知单账号凭据结构、无认证环境覆盖及检测到的管理配置冲突时支持；CLI/IDE 等共用凭据进程须先结束。未知、auto、keyring 和其他结构保留登录并说明原因 |
| Antigravity / macOS | 已有适配的个人账号 Keychain 模式，须先结束共用认证会话；回退文件为空、退出空壳或同身份时一并清理 Keychain、回退文件与超时标记，存在异号或非个人/损坏回退文件时拒绝自动退出 |
| Claude Code、旧版/未知 Antigravity、其他操作系统 | 尚不启用自动退出，账号池仍可移除；请在官方客户端退出 |

批量移除按同身份预览去重，始终保留客户端登录。CLI `ags rm <agent> <profile>` 先显示范围；加 `--yes` 执行，同步退出须另加 `--logout`，并自行先关闭客户端。

### 历史数据清理辅助

「设置 → 数据清理」当前提供 Codex 通用指令复制按钮。复制不读账号凭据、不维护历史账号名单、不执行删除，提示「已复制，尚未执行清理」。

指令要求用户的 Agent 现场检查版本、目录、认证后端及数据库结构，列出可识别账号，由用户选择目标和范围，再确认具体清单后执行。保护当前登录、共享/归属不明的数据及执行者自身依赖的数据；不把账号不在 AGS 中作为删除依据。找不到线索不等于没有残留。外部导出、浏览器登录、其他设备和服务端授权不在范围内。

### 验证与限制

自动测试使用假 HOME、假账号和进程内测试密钥，覆盖旧明文迁移及失败保留、密文损坏/密钥缺失、导入导出、切换与版本保护、删除范围变更、续期与移除并发、退出时账号变化、临时目录归属和设置复制行为。新实现未对真实账号池进行迁移或删除验收；Windows/Linux 系统密钥服务和自动退出均不得描述为真实环境验证通过。

主要实现：`credential-vault.ts`、`temporary-credentials.ts`、`storage-maintenance.ts`、`accounts.ts`、`client-logout.ts` 和 `cleanup-prompt.ts`。

## 各平台当前流程

| 平台与情景 | 添加与当前状态 | 切换方式 | 续期与额度 |
| --- | --- | --- | --- |
| Codex 文件登录 | GUI 在独立临时 `CODEX_HOME` 启动官方 app-server 登录，完成后保存；也可导入或用 `ags save` 保存当前文件登录。独立添加不改变当前账号 | 将目标 `auth.json` 应用到实际 `CODEX_HOME`；GUI 按上述流程退出与重开 | 查询时使用独立副本调用官方 app-server，接收刷新后的凭据并按版本写回；当前和备用账号均可查询订阅额度，API Key 不提供订阅额度 |
| Claude Code / macOS | 调用官方 `auth status` 读取当前登录；登录入口在 Terminal 执行 `auth login`，会改变当前配置目录的登录。文件凭据可导入管理 | 当前未实现 Keychain 保存与切换，不能把导入的文件备份当作已激活账号 | AGS 未实现订阅额度查询，也未实现账号池凭据自动续期 |
| Claude Code / 非 macOS 文件模式 | 代码保留 `.credentials.json` 保存与导入；当前状态来自官方 CLI，非订阅认证会限制文件账号管理 | 复用文件切换，已有终端需重开；该平台路径未做真实环境验证 | 仅展示可读取的身份与套餐字段，无额度查询 |
| Antigravity / 检测为旧版 | 从 `.gemini/jetski-standalone-oauth-token` 保存，或导入旧文件凭据 | 复用文件切换及桌面退出、重开流程 | 仅本地凭据识别，无额度查询或账号池自动续期 |
| Antigravity / macOS 2.x 个人账号 | 独立官方 ACP 浏览器授权后保存，或读取当前生效凭据（Keychain 优先，兼容个人账号文件回退）、导入个人账号凭据；添加不切换当前账号 | 共用流程保护当前与回退文件凭据、按认证布局更新 Keychain 或两个官方回退文件，再重开原桌面；其他共用认证会话需先结束 | 独立官方 CLI 会话读取套餐与 `/usage`；当前和备用账号都支持续期及额度刷新 |
| Antigravity / 版本未知或未验证平台 | 可管理文件备份，登录入口打开官方客户端 | 不应用尚未验证的认证存储 | 无独立额度查询 |

Codex 当前适配仅处理文件登录，不能据此切换 Keychain 登录。Claude Code 的非 macOS 说明是源码分支行为；GUI 自动打开 Terminal 的实现仅适用于 macOS。

Antigravity 的旧版/共用认证判断来自应用版本及 `agy` 安装线索；它是当前适配器的选择规则，不是对所有官方版本认证存储的保证。以上限制描述当前缺口，不限定后续产品能力。

## 应用退出与下载更新（已实现）

GUI 退出协调与账号切换分开：普通慢速网络额度查询不阻塞退出；真正退出 AGS 时停止接收新账号写操作，并在首次排空、退出确认弹窗及异步清理全阶段循环等待进行中的保存、切换、导入及已产生轮换凭据的回存临界区安全收尾（等待期间提示用户正在完成安全回存）；有未保存登录、待确认导入或未完成下载时说明将取消的范围，用户可以继续使用。原有凭据锁与写回保护保持。

应用更新只下载并打开 DMG，不自动替换应用，也不退出官方客户端。版本状态仅在设置中展示；下载与发布流程、真实分发验收边界见 [应用内下载更新](app-updates.md)。

## 后续调整方向（尚未实现）

AGS 的目标是账号能保存和再次使用、切换尽量少操作，并能查看可获取的额度。通用流程以现有代码为起点，随实际场景完善；不以任何单个平台当前实现为完整标准。

- 继续共用账号池和切换调度；平台适配负责取得、读取和应用认证状态、续期、客户端生效方式及额度获取。
- 调度按平台需要执行步骤：支持运行时切换时可省去重启，必须重新加载时复用现有退出与重开工具；步骤不要求各建一个模块。
- 接入新的存储或第二种额度来源时，按实际差异调整现有接口和 Codex 分支；不复制整套管理流程，也不预先搭建通用插件框架。
- 切换结果采用平台能可靠提供的依据；已有本地检查优先复用，新增运行时确认、重试或恢复须解决具体问题。额度失败单独展示，避免阻塞已经完成的切换。

| 平台 | 下一步需补齐或验证的部分 |
| --- | --- |
| Codex | 保持现有文件账号完整流程；遇到其他认证存储或客户端生效需求时补相应适配，不把当前流程冻结为标准 |
| Claude Code | 首版暂缓，保留适配代码；后续补齐 macOS 认证保存、激活和额度来源，再开放界面 |
| Antigravity | 已接入 macOS 个人账号切换、独立授权及当前/备用额度；后续按实际版本变化补兼容，不扩展未验证的企业认证 |

具体认证机制依据官方资料及原型结果确定；以下区分官方文档依据、本机兼容适配及实际验证范围。

## Antigravity 当前实现与验证

目标是用户主动选择账号后直接继续使用官方客户端。日常切换复用已有锁、凭据备份、版本检查、桌面退出与重开，不加入额外联网验收。桌面重开失败只提示手动启动；额度失败单独显示历史数据。

### 官方入口与本机适配

- [官方认证说明](https://antigravity.google/docs/install/)：App、CLI、IDE 共用个人账号认证；因此单独修改子进程 `HOME` 不能隔离 Keychain。
- [官方 ACP](https://antigravity.google/docs/ide/extensions/acp)：使用 `agy acp` 的 `initialize`、`authenticate`，由官方 CLI 完成 Google 浏览器授权和续期；AGS 不实现 OAuth 交换。
- [官方 `/usage`](https://antigravity.google/docs/cli/commands/usage/) 与 [CLI 更新记录](https://antigravity.google/docs/changelog?tab=cli)：使用 `agy -p /usage --output-format json` 获取后端额度，无模型对话；套餐取 ACP 认证结果。
- 桌面与 CLI 共用个人账号 Keychain 项 `gemini / antigravity`。小凭据通过标准输入更新并回读，写入命令须短于 4,000 字节。该限制也用于判断旧值能否安全回滚。[Apple 命令行工具实现](https://github.com/apple-oss-distributions/Security/blob/main/SecurityTool/macOS/security.c)
- 显式切换时，目标过长、原钥匙串值过长或旧条目仅能由原 AGS 读取时，可使用下面两个官方登录文件。若原来使用钥匙串，或首次使用文件存储，桌面会先说明凭据将存为两个权限为 `0600` 的本机文件。CLI 需要加 `--allow-file-storage`。已有文件登录可直接继续使用文件。旧版留下的空项和已识别编码内的残缺凭据也可经确认恢复。企业或无法识别编码的条目仍保留原件。
- AGS 先加密记录原状态，再分别写入并核对两个文件的完整内容和权限。活动账号标记保存成功后才尝试移除原个人钥匙串项。此后桌面与 CLI 即使没有超时标记也各自读到目标文件。失败时会核对现状，仅撤销本次仍可确认的变更；若进程被强制结束，下次主动切换时会先核对恢复记录。外部换号或退出时保留现场。后台续期沿用当前登录的存储方式。若桌面和 CLI 同时使用文件登录，两份属于原续期会话的文件都会得到新凭据，同邮箱的独立续期会话保留原件。
- 官方桌面端与 CLI 的文件认证回退分别为 `~/.gemini/jetski-standalone-oauth-token`、`~/.gemini/antigravity-cli/antigravity-oauth-token`（读写与清理前均校验父目录非符号链接），对应 1 小时超时标记 `~/.gemini/cache/antigravity-keyring-unavailable`、`~/.gemini/antigravity-cli/cache/antigravity-keyring-unavailable`。AGS 按真实优先级解析当前生效账号：桌面端存在活跃超时标记且桌面回退文件含有效个人凭据时取桌面回退（此时被遮蔽的异号 Keychain 同样纳入附属凭据保护，后台续期更新属于同一续期会话的既有回退文件，保留异号 Keychain）；否则 Keychain 含有效个人凭据时以 Keychain 为主；Keychain 为空时接受单一文件，或以账号身份及非空续期令牌相同确认两份文件属于同一会话。优先选择含可用访问令牌的完整副本，再比较可用时间。同邮箱的不同续期令牌须保留，无法确认来源时提示冲突。切换前先逐源比较凭据版本再按身份归组，确认指纹同时绑定全部凭据来源与标记生效状态并在首次写入前最终重检；前置检查失败零写入零回滚，发生部分写入后仅按变更记录逆序回滚本次 AGS 改动且此后未被外部修改或退出的来源（回滚自身失败时明确说明失败步骤与已保留状态）。
- 独立 CLI 的文件认证回退在临时 `HOME/.gemini/antigravity-cli/antigravity-oauth-token`。该路径和 Keychain 编码是本机验证的兼容细节，不是官方承诺不变的公共接口。

### 添加与切换

在 macOS 右上角的 AGS 菜单中，悬停「切换账号」即可选择可用的备用账号。普通切换在面板内完成，遇到未保存登录或需退出客户端等情况时，沿用主窗口的切换确认流程。[菜单说明](navigation-menus.md)

| 用户操作 | AGS 流程 | 对当前登录的影响 |
| --- | --- | --- |
| 保存当前账号 | 按上述优先级读取当前生效身份与凭据，沿用账号池去重、命名及备份 | 不改变 |
| 添加其他账号 | 独立临时目录运行官方 ACP，捕获官方浏览器 URL；普通/无痕/复制链接共用同一次会话；完成后读取并保存官方生成的凭据 | 不退出、不替换当前登录；取消时结束子进程并清理目录 |
| 切换账号 | 同步当前账号及回退文件中已入池的更新版本，对未入池的当前/回退个人账号走显式保存或丢弃确认；按上文的权限与长度约束更新并校验目标来源，清理已确认可移除的旧文件（失败时仅撤销本次写入且之后未变化的来源，保留官方端的新登录或退出），再重开原桌面并异步刷新额度 | 切换至目标账号，无须重复浏览器登录 |
| 凭据失效 | 既有「更新」入口独立重新授权，核对目标身份后原位更新；后台续期与原位写回仅清理退出空壳或同身份回退文件，不误删异号回退凭据 | 只在当前仍使用同一份失效凭据时同步替换，保留账号名称 |

添加账号与额度查询的子进程使用独立 `HOME`、工作目录和临时目录，并通过 macOS sandbox 拒绝读取/写入真实认证目录、访问 Keychain、安全服务和真实浏览器启动命令；只允许写入本次临时目录。对子进程清除认证覆盖环境变量。官方 CLI 因 Keychain 不可用而使用自己的文件回退，不伪装 SSH、不改全局活动账号。

首次授权由临时 `open` 辅助程序把官方链接交给 AGS，由现有浏览器入口打开。额度查询不打开浏览器；官方要求重新登录或明确返回刷新凭据失效时，标记为需更新，停止自动重试。网络及其他不明确错误继续按普通查询失败处理。

普通登录与无痕入口共用同一次授权会话。无痕入口支持 Google 与 OpenAI 官方登录域名，复用 Chrome / Chromium、Edge、Brave、Firefox 的私密窗口参数；Safari、其他未适配浏览器、启动失败或关闭自动打开设置时复制同一链接，供用户在本机私密窗口粘贴。链接约 15 分钟过期；完成授权后须回到 AGS 核对账号并保存，关闭添加窗口会取消未保存会话。

App、CLI、IDE 共用认证。日常切换检测其他正在运行的共用会话，提示用户先结束；GUI 与命令行会核对 AGS 临时目录的进程组记录和进程工作目录，识别另一 AGS 进程启动的隔离查询及其子进程。无法确认归属时保留会话保护。不强退无关编辑器或终端。

### 当前账号与备用额度

允许续期时，AGS 将指定账号复制到独立目录，通过官方 ACP 获取套餐，再用 `/usage` 查询额度。与运行中的官方端共用会话时，只使用尚有效的访问令牌查询额度，隔离目录不提供续期令牌。若需等待客户端续期，详情保留上次成功取得的数值和时间，按本次检查时间安排下次尝试。结束后按账号身份与凭据版本写回续期结果；备用账号只更新自己的池文件，不写当前 Keychain。即使续期后额度请求失败，也保留已生成的新凭据。

复用已有缓存、跨进程身份锁、最多三项并发的 GUI 队列和失败退避。当前每 60 秒、备用每 5 分钟到期补查；单次检查至少间隔 30 秒。额度窗口重置后补查，失败保留带时间的历史，不能推算恢复余额。

GUI 以 Gemini 作为主额度和默认排序依据；当前卡片直接显示其实际周期，其余模型组按内容长度自然排列。备用卡片与单行只保留 Claude / GPT 摘要（窄卡简称 C/G），Argon 等组通过原有右键详情查看；Pro 与 Ultra 不强行补齐模型桶。没有返回的比例保持未知，不将其他组当作 Gemini，不展示平台未提供的 Credits。
