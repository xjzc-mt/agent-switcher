# 额度刷新

本页描述 Codex 与受支持的 Antigravity 个人账号共用额度刷新流程；Claude Code 尚未接入。各平台整体行为见 [账号管理流程](account-management.md)。

账号池的目的是帮助用户选择下一次使用的账号。应先展示已有快照，再按数据时效补查；查看倒计时、搜索、切换展示模式都不应触发网络查询。

## 入口与反馈

- 当前账号和备用账号：右键打开账号详情，再选择「刷新额度」。卡片和单行模式均移除表面的单个刷新图标。
- 右键直接打开现有详情，无额外菜单。昵称、邮箱和 Credits 边角不再打开详情；键盘聚焦账号后可按 Enter 或 Shift+F10。仅打开详情不会触发查询。
- 详情 140ms 淡入、100ms 淡出，仅改变透明度，减少动态效果时无动画。鼠标打开后关闭不强制聚焦账号；键盘入口关闭后恢复账号焦点，不留下鼠标操作造成的整行高亮。
- 账号详情：保留异常说明和更新时间；「刷新额度」显示「等待刷新…」或「刷新中…」，结果同步到详情与账号池。
- 顶部「刷新全部」：查询当前平台全部账号，逐个更新，显示完成数量；查询失败也计入完成数量，最后单独报告失败数。

正在查询的账号禁止重复点击。已经排队、尚未开始的账号仍可点击，以提高其优先级。刷新不会切换账号或重启客户端。

## 自动刷新策略

| 情况 | 行为 |
| --- | --- |
| 当前账号 | 上次检查完成 60 秒后补查 |
| 备用账号 | 上次检查完成 5 分钟后补查 |
| 额度窗口即将重置 | 重置后 10 秒补查，并满足距上次检查完成至少 30 秒 |
| 暂时查询失败 | 保留上次成功额度，连续失败按 2、5、15 分钟退避 |
| 凭据失效、无凭据、明确不支持 | 停止自动重试；手动刷新可重新检查 |
| 窗口最小化或不可见 | 不启动新的自动查询；已开始的查询允许完成 |
| 返回窗口 | 读取账号状态，只查询到期数据，重复焦点事件合并 |

倒计时每 30 秒仅在本地更新。IPC 或文件操作失败后，界面至少等待 60 秒再自动尝试。如果查询已经完成，但随后读取账号列表失败，界面到时先重读本地列表，取得各账号的截止时间后再决定是否查询。手动刷新仍可用。

## 请求协调

当前账号、备用账号、详情、全量刷新和自动刷新共用一个最多并行 3 个查询的队列，限制同时进行的独立账号查询数量。某个账号查询缓慢时，其他查询完成后会继续补入排队账号，无需等待整组结束。单账号手动请求优先于尚未开始的批量任务；当前账号到期补查优先于普通备用账号自动查询。已经开始的查询不会被抢占。

同一账号正在排队或查询时，新的请求复用同一个任务。手动操作可把排队中的自动请求升级为强制查询；已经运行的查询直接复用结果。批次尚未结束时，手动和自动触发均复用本轮已完成的账号结果。

同一份凭据每次检查完成后至少间隔 30 秒再查询，期间手动刷新复用最近结果和原始检查时间。手动刷新在此间隔后可以绕过常规缓存和失败退避。此检查由后台在取得身份锁后执行，已保存账号在重命名、重启应用和 CLI 请求时同样生效。更换凭据后可以立即验证新凭据。

查询使用独立的凭据副本。不同身份可并行，GUI 和 CLI 对同一身份（包括同一账号的不同别名）的查询仍通过跨进程锁依次执行；等待外部 CLI 时，其他账号仍可改名、切换或移除。与客户端主登录或回退文件身份相同、或共用续期令牌的账号，在官方客户端运行或进程状态无法可靠确认时，只走保证不轮换的查询路径（Codex 仅在访问令牌有效期内以只读副本查询且不写回实时凭据，Antigravity 仅向隔离的官方 `/usage` 提供有效访问令牌，不启动 ACP 认证），官方客户端自行续期后自动同步回池。并发数 3 是单个 GUI 队列的上限，额外运行的 CLI 查询不计入此上限。写回前核对身份与凭据版本，当前或备用 Codex 账号在续期补全 `sub` 升级身份时按查询前已确认的身份与凭据版本同步对应原卡片及同版本别名。批量刷新逐项更新画面，批次结束时重读账号池，以反映期间的外部登录或改名。

Codex 普通额度查询会对照账号登记的邮箱、令牌中的用户与工作区，以及 CLI 实际返回的账号信息。收到其他账号的身份时，卡片会显示错误并保留原凭据。同邮箱的不同用户或工作区分别核对，身份冲突的旧额度不会显示为当前结果。

旧导入凭据只有 access token 和 refresh token，或缺少可核对的工作区时，AGS 会在客户端空闲时用原 refresh token 向官方服务换票，从新颁发的令牌建立绑定。只有通过原有身份约束的结果才写回原账号及同版本别名，临时使用的工作区占位值不会写入账号池。繁忙会话延后这次验证。

换票已成功并确认身份后，即使后续额度查询失败，也会保存新凭据并单独报告额度错误。如果换票消耗了旧令牌但新身份与登记信息冲突，AGS 保留可恢复的副本，并拦住手动和自动重用已消耗的续期令牌。外部候选验证失败时仍保留这项保护及恢复位置，官方重新登录取得新令牌后可以继续刷新。

同一身份、同一凭据版本的账号共享查询结果和检查时间，各自保留昵称与备注。“保存当前并切换”留下的保护备份可能与后来保存的同邮箱正式账号持有不同凭据。此时刷新备份使用备份自己的凭据和 5 分钟间隔，刷新当前卡使用客户端凭据和 60 秒间隔。官方客户端自行续期后，当前卡可跟进新版本。如果池内凭据更新或双方无法比较新旧，当前卡只读查询实际登录，保留池内版本。

待验证凭据与原登录分别记录检查状态。客户端繁忙而延后验证时，按候选凭据的检查时间安排下一次尝试，并保留原登录已有的续期保护。某个账号的凭据文件不可读时，暂停该卡的自动查询；重新加载状态发现文件已恢复后，再按当前版本判断。Codex 登记邮箱冲突的本地检查也遵守失败退避。

查询已完成但本地写入失败时，同一 AGS 进程在 30 秒内再次请求该版本会返回原错误。对于可能轮换的查询，临时恢复目录保存平台、身份和输入续期令牌的组合摘要。如果新凭据未能确认写回，后续进程可根据这份记录识别原输入，停止再次换票。重新授权取得的新令牌仍可验证。此保护依赖恢复目录继续存在，旧版本留下的目录没有这项摘要。

每个账号独立报告结果。一个账号出现网络、IPC 或文件异常不会停止其他账号。后台查询失败不会逐个弹出通知；错误通过详情说明和缓存状态呈现。

Codex 的额度窗口、重置卡与 Credits 一并来自同一次账号查询，不能根据套餐名、剩余时间或上一份余额推算新值。平台没有返回的数据保持未知。

Antigravity 通过独立官方 ACP 取得套餐，通过官方 `/usage` 取得各模型组的周期额度。独立备用账号在隔离目录查询和续期，续期结果写回对应账号。各模型组的重置时间参与补查。

与运行中的客户端共用登录时，AGS 将访问令牌单独交给隔离的 `/usage`。到期时间优先读取 `token.expiry`，缺少该字段时读取同一条记录的根级 `expiry`。如果当前凭据缺少可用的访问令牌，AGS 也会检查官方认证来源及对应账号卡中身份和续期令牌均相同的副本，优先使用到期时间明确且仍有效的令牌。若同一登录只有未标注到期时间的访问令牌，AGS 原样省略到期时间，交由官方 CLI 只读查询一次。已知过期的令牌跳过。暂时无法查询时，主卡保留已有额度，账号详情显示上次更新时间和等待原因。手动刷新时也会短暂显示该原因。官方客户端更新登录状态后，AGS 会在下次自动刷新时重新查询。本次等待仍计入刷新间隔。
