# 额度刷新

本页描述 Codex 与受支持的 Antigravity 个人账号共用的额度刷新流程。各平台整体行为见 [账号管理流程](account-management.md)。

账号池的目的是帮助用户选择下一次使用的账号。应先展示已有快照，再按数据时效补查；查看倒计时、搜索、切换展示模式都不应触发网络查询。

## 入口与反馈

- 当前账号和备用账号：右键打开账号详情，再选择「刷新额度」。卡片和单行模式均移除表面的单个刷新图标。
- 右键直接打开现有详情，无额外菜单。昵称、邮箱和 Credits 边角不再打开详情；键盘聚焦账号后可按 Enter 或 Shift+F10。仅打开详情不会触发查询。
- 详情 140ms 淡入、100ms 淡出，仅改变透明度，减少动态效果时无动画。鼠标打开后关闭不强制聚焦账号；键盘入口关闭后恢复账号焦点，不留下鼠标操作造成的整行高亮。
- 账号详情：保留异常说明和更新时间；「刷新额度」显示「等待刷新…」或「刷新中…」，结果同步到详情与账号池。
- 顶部「刷新全部」：查询当前平台全部账号，逐个更新，显示完成数量；查询失败也计入完成数量，最后单独报告失败数。

正在查询的账号禁止重复点击。已经排队、尚未开始的账号仍可点击，以提高其优先级。刷新不会切换账号或重启客户端。

## 自动刷新策略

在「设置 → 偏好设置」中分别独立设置「当前账号自动刷新」与「备用账号自动刷新」，互不耦合。设置立即保存，AGS 按各账号上次检查时间重新安排到期检查。

| 设置项 | 可选档位 | 小菜单额度显示为缓存的时间 |
| --- | --- | --- |
| 当前账号自动刷新 | 1 分钟（默认） / 3 分钟 / 5 分钟 / 仅手动 | 1/3/5 分钟档超过 5 分钟；仅手动超过 30 分钟 |
| 备用账号自动刷新 | 5 分钟（默认） / 15 分钟 / 30 分钟 / 仅手动 | 5 分钟档超过 5 分钟；15 分钟档超过 16 分钟；30 分钟档超过 31 分钟；仅手动超过 30 分钟 |

- 定时档在额度窗口重置 10 秒后可提前补查，两次检查至少相隔 30 秒。暂时失败按 2、5、15 分钟退避，等待时间取退避与该账号所选周期中的较长者。凭据已失效、已退出或不支持额度的账号停止自动重试。
- 首次启动或从隐藏恢复可见时先读取本地状态，开启定时的范围（当前或备用）只补查已到期的账号。窗口隐藏后排队的自动查询暂停，已开始的查询可完成。可见窗口内的焦点变化不会触发查额。
- 设为「仅手动」的范围（如仅备用账号设为手动、当前账号保持 1 分钟，或两者均设为手动）关闭对应范围的定时、重置点补查及导入或保存后的附带查额。用户可在账号详情、顶部或小菜单主动刷新，手动切换成功后仍会检查目标账号额度。暂存凭据在主动刷新时验证。

倒计时每 30 秒仅在本地更新。查询的 IPC 或文件操作失败后，按当前账号或备用账号的已选周期再尝试。如果查询已经完成，但随后读取账号列表失败，界面到时先重读本地列表，取得各账号的截止时间后再决定是否查询。手动刷新仍可用。

## 请求协调

当前账号、备用账号、详情、全量刷新和自动刷新共用一个最多并行 3 个查询的队列，限制同时进行的独立账号查询数量。某个账号查询缓慢时，其他查询完成后会继续补入排队账号，无需等待整组结束。单账号手动请求优先于尚未开始的批量任务；当前账号到期补查优先于普通备用账号自动查询。已经开始的查询不会被抢占。

同一账号正在排队或查询时，新的请求复用同一个任务。手动操作可把排队中的自动请求升级为强制查询；已经运行的查询直接复用结果。批次尚未结束时，手动和自动触发均复用本轮已完成的账号结果。

同一份凭据每次检查完成后至少间隔 30 秒再查询，期间手动刷新复用最近结果和原始检查时间。手动刷新在此间隔后可以绕过常规缓存和失败退避。此检查由后台在取得身份锁后执行，已保存账号在重命名、重启应用和 CLI 请求时同样生效。更换凭据后可以立即验证新凭据。

不同身份可并行，GUI 和 CLI 对同一身份的查询通过跨进程锁依次执行。Antigravity 查询在此队列内逐个执行，额外运行的 CLI 查询另计。等待外部 CLI 时其他账号仍可改名、切换或移除。写回前核对身份与凭据版本。Codex 续期补全 `sub` 时依原身份和版本同步原卡片及同版本别名。批量刷新逐项更新画面，批次结束时重读账号池。

Codex 普通查额时，已核对身份的访问令牌若还有超过 60 秒的明确有效期，先用去掉真实续期令牌的只读副本查询。临近到期、已过期或有效期未知时，允许续期的登录才进入可写查询。如果只读查询明确返回鉴权拒绝或未取得登录，AGS 重新检查凭据版本和客户端占用，条件仍满足时只升级一次。网络故障不会触发换票。与运行中客户端共用的登录保持只读。

官方 CLI 可能在读取账号时自行续期。只读副本报告访问令牌被撤销或无法续期时，独立账号在上述核对通过后用真实凭据续期一次。官方客户端正在使用同一登录时，等待客户端续期或关闭后再刷新。两种情况下，已有额度及最近成功时间均可在详情查看。

官方明确拒绝真实续期时，已保存的账号进入「凭据失效」组，可从详情点击「更新凭据」重新登录。已经续期成功、随后额度接口单独拒绝新访问令牌时，保留已核对的新凭据，详情提示稍后刷新。

限流时提示稍后刷新，开启自动刷新的账号按设置重试。订阅或工作区受限时提示到网页端确认状态；网络、代理或服务错误提示检查连接后重试。提示使用固定文案，故障报告只记录可确认的步骤和脱敏错误码。

Antigravity 共用登录也优先只读查询。只有确认官方端运行且当前登录的归属与存储来源可核对时，原「刷新」才可请求官方 CLI 在原登录上续期。

Codex 普通额度查询会对照账号登记的邮箱、令牌中的用户与工作区，以及 CLI 实际返回的账号信息。收到其他账号的身份时，卡片会显示错误并保留原凭据。同邮箱的不同用户或工作区分别核对，身份冲突的旧额度不会显示为当前结果。

旧导入凭据只有 access token 和 refresh token，或缺少可核对的工作区时，AGS 会在客户端空闲时用原 refresh token 向官方服务换票，从新颁发的令牌建立绑定。只有通过原有身份约束的结果才写回原账号及同版本别名，临时使用的工作区占位值不会写入账号池。繁忙会话延后这次验证。

换票已成功并确认身份后，即使后续额度查询失败，也会保存新凭据并单独报告额度错误。如果换票消耗了旧令牌但新身份与登记信息冲突，AGS 保留可恢复的副本，并拦住手动和自动重用已消耗的续期令牌。外部候选验证失败时仍保留这项保护及恢复位置，官方重新登录取得新令牌后可以继续刷新。

同一身份、同一凭据版本的账号共享查询结果和检查时间，各自保留昵称与备注。“保存当前并切换”留下的保护备份可能与后来保存的同邮箱正式账号持有不同凭据。此时刷新备份使用备份自己的凭据和备用周期，刷新当前卡使用客户端凭据和当前账号周期。Antigravity 在官方客户端重新登录同一邮箱后，当前卡仍可按下文的共享条件续期。账号池保留独立登录原有的凭据和额度快照。

待验证凭据与原登录分别记录检查状态。客户端繁忙而延后验证时，按候选凭据的检查时间安排下一次尝试，并保留原登录已有的续期保护。某个账号的凭据文件不可读时，暂停该卡的自动查询；重新加载状态发现文件已恢复后，再按当前版本判断。Codex 登记邮箱冲突的本地检查也遵守失败退避。

Codex 只为可能续期的查询登记待写回记录。刷新或准备切换时，AGS 在身份锁和账号池锁内核对同一登录的中断记录，兼容旧版仅登记身份和续期令牌摘要的目录。

- 写入进程仍在运行、或无法证明已退出时，保留目录并提示稍后刷新。Windows 同次开机的旧记录只有直接子进程 PID 时，也保留到能够确认全部写入进程退出。
- 写入进程已退出且目录、文件归属与权限核对通过后，没有输出或访问令牌和续期令牌均未变化的副本可直接清理。有合法轮换时，先核对用户、登记邮箱及工作区，写回同版账号副本并复读确认。中途退出可从已写回或尚未写回的副本继续。
- 工作区冲突、文件不可信或有多个不一致的轮换结果时保留证据。共用登录的官方客户端运行期间，AGS 不覆盖该客户端持有的凭据。Antigravity 的恢复规则见下文。

每个账号独立报告结果。一个账号出现网络、IPC 或文件异常不会停止其他账号。后台查询失败不会逐个弹出通知；错误通过详情说明和缓存状态呈现。

Codex 的额度窗口、重置卡与 Credits 一并来自同一次账号查询，不能根据套餐名、剩余时间或上一份余额推算新值。平台没有返回的数据保持未知。

### Antigravity 个人账号

**当前账号。** Antigravity 桌面运行或其状态不明时，AGS 将同一登录的访问令牌单独交给隔离的官方 `agy -p /usage --output-format json`。先检查 `token.expiry`，该字段缺失时读取根级 `expiry`。同一登录只有未标注到期时间的令牌时可以尝试只读查询。

无可用访问令牌或官方明确拒绝访问令牌时，AGS 才考虑共享查询。macOS 支持已解锁的唯一官方钥匙串项，以及钥匙串为空、两端均为当前用户所有的 `0600` 普通文件且属于同一次个人登录的情形。共享调用前后都检查登录归属、回退标记及冲突来源。同一邮箱与续期令牌核对通过后使用本次官方 `/usage` 返回的额度。

Windows 源码版对可确认的当前个人登录同样走官方共享续期，以便官方客户端自行处理续期后变长的凭据。备用账号在独立的临时主目录运行官方 CLI，代理配置保留，支持传入指向本机的代理地址。查询返回的套餐名称为 Google AI Ultra 时，AGS 依据已核实的套餐标识显示 5× 或 20×。只取得额度时保留上次的套餐信息。[官方 CLI 套餐字段](https://antigravity.google/docs/changelog) · [两档返回值对照](https://github.com/farion1231/cc-switch/issues/9317)

Windows 备用查询会禁用令牌中的宿主用户 SID，为该次查询分配独立的限制 SID。AGS 解析用户主目录和漫游应用数据目录的重定向目标，再核对受保护目录的防写权限、`.gemini` 两端的已知凭据和回退标记，以及完整的 AGS 账号池目录。其他 Gemini 项目、缓存和链接不会参与扫描。已知凭据可被受限令牌读取、受保护路径含意外链接或检查无法完成时，查询在启动前结束。[Windows 受限令牌](https://learn.microsoft.com/en-us/windows/win32/secauthz/restricted-tokens)

受限令牌可以读取和执行官方 CLI 时，AGS 直接从安装位置运行。否则使用当前用户本地应用数据下的只读程序缓存，按源路径、文件标识、大小、时间和 SHA-256 识别版本。连续查额度可复用同一份程序。查询凭据仍在各自的临时主目录内，代理证书仅复制公开 CA 材料。超时会等待 Job 排空，未确认的续期结果留待恢复。

共享查询未取得可归属的新额度时，自动查询按当前档位与失败退避安排下次检查。同一次登录出现新令牌后，下次刷新可立即查询。

桌面回退标记有效且钥匙串暂不可读时，当前卡可从受当前用户保护的官方桌面文件确认身份，用同一次登录中带有效期的访问令牌查询。提交前重新核对标记和登录。此时暂停同步凭据，备用账号和待验证更新也须等官方登录来源可核对后再续期。

文件来源不符合上述条件或官方端运行状态不明时，仍只跟随同一次登录发布的可用访问令牌。网络、429、服务故障和浏览器登录提示都不会触发共享续期。未取得新额度时保留最近一次成功时间。桌面连续闲置跨两次自然到期的验收见[第 05 问](account-management.md#antigravity-lifecycle)。

**备用账号。** 有可用访问令牌且套餐已知时可直接查额度。官方明确拒绝该令牌时，重新确认这份凭据属于备用账号且允许续期，再在同一身份锁内调用一次隔离的官方 ACP。仍被客户端使用的登录或有待恢复写入的凭据保持只读。需要换票时，先在账号池内加密登记输入，再由隔离的官方 ACP 认证；新凭据的写回与本次额度查询分别确认。刷新、切换或导出作为中断后的第一个操作，都会先核对同一份恢复记录。原临时目录被系统清理时，已有加密结果可恢复；只有发送记录而没有可确认结果时，保留记录并暂停重用旧续期令牌。有仍有效的访问令牌时可以只读查额度，切换与导出则须先确认凭据版本。

**官方查询失败。** AGS 分别记录限流、网络、服务不可用和访问令牌遭拒。断网时官方 CLI 也可能转入浏览器登录。若本次仅查额度，AGS 会结束查询并保留上次结果。若备用账号已发起续期且未收到明确结果，AGS 保留恢复记录，暂停使用旧令牌。官方明确拒绝该登录凭据时，才将其标为已失效。
